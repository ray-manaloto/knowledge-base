# Q: Can datamodel-code-generator replace hand-written generator and drift-check wrappers, and what breaks if you try?

## Answer

datamodel-code-generator 0.75.1 ships both halves of what eight hand-written
files in schemas/ were doing: `--all-jobs` reads named jobs from
`[tool.datamodel-codegen.jobs.*]` in pyproject.toml, and `--check` exits 1 on a
difference without writing. Two mise tasks replaced six; 628 lines deleted
against 167 added (#569).

THE TRAP, and it is silent. `output-model-type = msgspec.Struct` auto-enables
`use-annotated` (which enables `field-constraints`) ONLY on the direct-CLI path:
`_prepare_cli_config_args` sees the args passed alongside `--all-jobs` and never
a job table's own fields. A jobs-table conversion therefore drops EVERY
`Meta(...)` constraint from every model, with no warning — `Annotated[int,
Meta(ge=0)]` becomes a bare `int`. Both keys must be named explicitly in the base
table. Caught only because the acceptance criterion was byte-identity of the
committed models, not "the config looks right".

Of the pair, `use-annotated` is load-bearing and `field-constraints` is inert on
its own — measured by mutation arm, not reasoned: dropping `field-constraints`
alone SURVIVED the drift gate, dropping `use-annotated` alone and dropping both
each killed it.

TWO COUPLINGS worth not rediscovering. (1) Generated bytes depend on the OUTPUT
PATH: the generator runs ruff with cwd set to the job's output directory and ruff
walks up from there for config, so an output outside the repo silently gets
ruff's 88-column default against this repo's 100. A first probe of this change
lied for exactly that reason. It also means the deleted checkers'
generate-to-a-tempdir-and-compare pattern was structurally wrong and only ever
passed by coincidence; the native `--check` compares in place. (2) The drift gate
cannot see a formatter rewrite: generation and checking run the SAME pass, so a
ruff bump that rewrites generated code reddens the gate once, a human
regenerates, and the altered model ships green. Containment is the models' own
tests, not the gate.
