# Q: Should a recurring judgement failure become a new .claude/rules entry by default?

## Answer

Three of the four readers independently recorded a MEASURED verdict that writing
the lesson down did not work. Handoffs: this class is not fixed by more prose,
over six occurrences of an already-eager, already-detailed rule. Memories:
writing the lesson down has now failed twice consecutively, so the remedy is
structural. Issues: a rule violated after being written is this repo's own
stated trigger for a machine layer.

Supporting measurements: compliance with query-the-graph-FIRST, the founding
premise stated eagerly in CLAUDE.md, was 2 of 7. The branch-FIRST invariant is
eager and was violated with six commits onto main. Credentials reached
transcripts three times, the last AFTER the prohibition was in every lane
prompt.

And the readers' combined remedy was 22 rule additions, costed at +18,350 bytes
on a 100,810-byte eager base, about +4,600 tokens in every session forever.

The criterion adopted instead, and it is reusable: a finding becomes eager rule
text only if all three hold. One, no mechanisable form exists. Two, no existing
rule already covers it, established by a control-armed grep rather than
assumption. Three, its trigger is a behaviour, so path-scoping would make it
absent exactly when needed.

One file cleared all three: arm-your-own-work.md, 113 lines, +5.3% eager cost
instead of +18.2%. The other 17 amendments are parked in issue 216 with their
per-row byte estimates, to be decided per row rather than adopted wholesale.
