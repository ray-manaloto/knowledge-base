One version, two spellings

A tool bump has to write the same release into two files. The two files disagree about how to spell it — and the engine spelled it one way for both.

When currency apply bumps a tool, it edits two committable files. Both are about hk 1.56.1. Neither wants the same characters.

mise.toml holds a pin, and a pin takes a bare version: 1.56.1. sources/hk.manifest holds a ref, and a ref takes the git tag: v1.56.1. One character apart, and only one of them is right in each place.

The engine carried a single resolved string and wrote it to both. The manifest got what it wanted. The pin did not.

Where the v survives

The interesting question is not why the pin was wrong. It is why a v was still attached to the string by the time anything wrote it. Three functions decide that, and each one is doing exactly what it was written to do.

Why nobody saw it

The engine has a config key for exactly this: tag_prefix. Two tools declare one. Those two are the only two that cannot exhibit the defect — because declaring a prefix is what causes the strip at upstream.py:574.

Tool Upstream tag tag_prefix Pin it would write Verdict
codex rust-v0.149.1 "rust-v" 0.149.1 SAFE
firecrawl-cli v1.23.1 "v" 1.23.1 SAFE
hk v1.56.1 none v1.56.1 HIT — live
agnix v0.50.0 none v0.50.0 WOULD HIT
fnox v1.34.0 none v1.34.0 WOULD HIT

Only hk actually reached apply. agnix and fnox were minor bumps, and the engine refuses to auto-apply anything above patch level — so they were bumped by hand and never went through the broken path.

The gate that blocks minor bumps is currently what limits this defect's blast radius. Patch bumps are exactly the ones apply is allowed to make unattended. — issue #499, as filed

The arm that survived

Four mutation arms were written against the fix. Three died on the first run. One survived — and it was the interesting one, because it was measuring a claim I had written into the code's own docstring.

The reduction is one expression. I had claimed the order of its two halves mattered: 

value.removeprefix(prefix).lstrip("v")

The arm swapped them and expected a test to go red. Nothing failed. The reason is plain once looked at: lstrip("v") cannot eat a character of a prefix that does not begin with a v, so on every real input the two orders return the same string. The swap was an inert mutant — it changed the source without changing any behaviour a test could see.

The code was right. The sentence was not. The docstring now says the order is not load-bearing and says why, and the arm was replaced with one that breaks the property that is: that the prefix is stripped by name rather than guessed at. That arm dies.

A surviving arm reads as coverage. This one measured nothing at all — and it would have shipped a confident, wrong sentence attached to correct code. — recorded in the arms spec rather than deleted

What was measured, and where

  • Version.parse keeps raw verbatim and cleans only its comparison key — upstream.py:151, upstream.py:159.
  • github_versions returns max(stable).raw after stripping the declared prefix and nothing else — upstream.py:574, upstream.py:581.
  • Exactly two tools declare a tag_prefix — currency.toml:1844 (codex), currency.toml:2072 (firecrawl-cli).
  • Every tag spelling in the table above was re-derived live this session against gh api repos/<repo>/releases, not taken from the ticket. codex's newest release is a prerelease (rust-v0.150.0-alpha.9), which github_versions excludes, so the table shows its newest stable tag. The probe was control-armed: a guessed org returned 404 while jdx/hk returned real tags, so an absent result would have been distinguishable from an unasked question.
  • The manifest was written correctly by the fallback, not by design: _tag_candidates tries v<version> after the prefixed candidate — manifest.py:248.
  • mise ls hk reporting the pin (missing) was measured live on the ticket, not in this session. It is not asserted by any test here — no unit test in this repo can reach mise's resolver.
  • Arms: 4/4 died, 1/1 control held, after A3 was replaced. Gates on the working tree: lint · test · brain-audit · eval · graph-size · hk-test, 6/6.

What this does not claim

That #499 is the only place a resolved string is written to a target that spells it differently. The arms can only show that this one can fail. Whether normalising at write time beats normalising in github_versions is a design call, argued in the commit and not settled by any test.
