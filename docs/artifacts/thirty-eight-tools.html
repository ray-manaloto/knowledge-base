Tool survey · measured 2026-08-26

Thirty-eight tools

Five were actually run. Sixteen were ruled out. And the reason that ruled out the most promising survivor turns out to rest on something later measurement refuted.

The question was: which of these have a real prototype, and which are pending or eliminated? Answering it meant reading four research reports, two /tmp directories, a plan document and the open issue backlog — because the answer had never been in one place.

38 candidates. Here is where they sit.

The three that work

That sequenceDiagram row is worth pausing on: the library was recalled from memory as a candidate, confirmed to exist, run successfully — and then disqualified on a zero-byte LICENSE. It works and cannot be used.

The reason that expired

The most promising untried path is type-aware analysis via a language server — the only approach that can follow a value across a function boundary, which is the exact gap every AST tool shares.

It was ruled out. The reason, verbatim:

REJECT: LSP call-hierarchy — python-only, needs a live server, strictly weaker than the AST graph we own.

Two of those three clauses still hold. The third does not.

And ty was never the thing that was rejected

The verdict covers the generic pylsp/pyright category. ty is not named in any of the four research reports or the tool survey. It is pending — never probed, and already pinned in this repo.

Meanwhile issue #276, open since 2026-08-11 and filed thirteen days before that rejection, specifies a full ty-based pipeline with twelve acceptance criteria and eight control arms — and appears in none of the reports that rejected the category it belongs to.
