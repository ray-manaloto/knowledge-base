What reaches what

Every graphify command, traced to the mise task and the Python function that reach it — and the 16 that nothing reaches at all.

The question was simple to ask and had never been answered: for each thing graphify can do, what in this repo actually calls it? Nobody could answer it, because the answer lives across three files that don't reference each other — mise.toml, cli.py, and graphify's own command table.

So it got traced. 83 literal commands, every one followed through the chain.

Where the 83 commands actually land

The raw split looks alarming — 41 MISSING — and most of it is not a gap. Two thirds of the missing surface is missing because a standing invariant forbids it.

The most useful row is the one that isn't a gap

query is covered — a task reaches it, a function calls it — and it still lands on a CLI subprocess, because graphify.serve._query_graph_text is private and has no public alternative anywhere. That's the single fact that decides the SDK question for the whole repo: the heaviest-used verb cannot move to the SDK without importing an underscore, which is the violation that got an entire layer deleted on 2026-08-24.

The finding that needs a decision, not just a note

graphify's semantic cache is keyed on (mode, prompt fingerprint, content hash) — and nothing else. The word backend appears zero times in cache.py.

So if Claude's tokens run out and the same files are re-extracted on openai-cli, the cache returns a silent hit carrying Claude's output, labelled as an OpenAI run. No provenance is recorded in the cache entry or in the graph. The only existing lever is --force, which discards the entire cache rather than partitioning it.

This matters precisely because backend failover was asked for: the failover works, and it would quietly launder one model's output as another's.

And one thing already exists that nobody used

graphify ships --fallback-backend. It fires only on a total zero-success run, not on mid-run depletion — so it is not the feature that was wanted, but it is the hook the wanted feature should be built on rather than beside.
