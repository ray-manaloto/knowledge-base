The one that would have broken the run

Both READMEs teach CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1 claude plugin marketplace add …. Under Bash(claude *) that line does not start with claude, and a permission rule must match each subcommand independently (cd /work && claude … fails the same way). In -p mode nobody can approve the denial. The fix is a prompt constraint — commands issued bare, the variable is already exported — not a looser allowlist.

A fix inside the fix

My round-2 addendum asked for a schema-free provenance check: installPath must start with /work/. It could never pass — installPath is always a plugins/cache/… copy; the /work/aggregated-research I had read was session 2's init.plugins[].path, a different field with a look-alike value.
