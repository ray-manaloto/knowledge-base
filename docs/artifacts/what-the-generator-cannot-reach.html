What the Generator Cannot Reach

You asked for decide()'s six arguments to be wrapped into a request object generated by datamodel-code-generator. The resync is done. The wrapping has a real obstacle, and it is worth thirty seconds before an hour.

The generator makes data. These arguments carry behaviour.

datamodel-code-generator turns a JSON Schema into a model. A JSON Schema can describe a string, a number, a nested object — it cannot describe a method. So the models it produces are pure data, by construction, and this repo's three existing generated modules prove it.

Measured this session, not assumed

  • The three generated modules import only enum, typing, msgspec, and each other — never a hand-written kb_setup type.
  • 41 generated classes, 0 methods and 0 properties among them.
  • SyncStatus.drifted / .ok (sync.py:88-94), ViewStatus.quiet (views.py:122), Observation.usable / .differs_from (issues.py:43-68) — all read by the gates.

Four ways forward

Only the last two actually remove the argument count. I have a recommendation but the call is yours, because option 3 is a real change to the engine's core and you may want it for other reasons.

1

Generate the request object anyway

does not work

The generated container would carry generated field types, and three of them would lose the properties the gates call. It compiles and then the gates read attributes that no longer exist.

2

Hand-write a six-field frozen dataclass

works · ~10 lines · recommended

A DecisionRequest holding the existing types unchanged. Removes the suppression, keeps every property, touches the call sites and nothing else. The honest note: it is not generated, so it sits outside the codegen discipline you asked for.

3

Make the whole currency type family generated

works · large · changes the engine's shape

Describe Observation, SyncStatus, UpstreamStatus, ViewStatus and Reviewed in schemas, generate them as Structs, and move every property out into module functions. This is the version that genuinely honours "the ONE owner of generated models" — and it rewrites the core of the tool-currency engine to get there.

4

Raise max-args to 6

works · no object at all

The repo has never set it, so the 5 is ruff's default. No suppression, no refactor — but the check relaxes everywhere, not just here.
