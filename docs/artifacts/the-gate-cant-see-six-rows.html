Three ways to get a guard past the new gate

The gate is supposed to notice when a guard exists that nobody has signed off on. All ten checks pass. I tried three ways round it; all three worked.

Add a brand-new guard nobody approved
worst · no file editing needed

Write an ordinary new guard and wire it up the ordinary way. The gate only recognises one of the four normal ways to wire something up in this language — use any of the other three and the guard simply doesn’t exist as far as the gate is concerned. This is the exact thing the gate was built to prevent.

wired the one way it knows → caughtwired the second way → cleanwired the third way → clean

Delete a guard from the approved list
3 of 11 files

Three guard files can be struck off the list and the gate still reports OK — and one of the three is the file that runs the other eight.

deleting a watched one → FAILdeleting any of the three → clean

Invent a guard that was never written
3 of 21 entries

Three entries are skipped entirely. You can delete one, or make one up for a guard that doesn’t exist, and the gate credits it either way — so the headline number it publishes can be typed in by hand.

deleting a watched entry → FAILinventing one → clean

Nothing is less safe today than yesterday. No guard stopped working; every one of them still runs. What’s wrong is the gate’s promise — and twelve more tickets are planned on top of the number it publishes.
→ One decision: fix all three now, or fix the worst two now and ticket the third.
