The Research Ladder

Order the sweep by how a wrong answer fails. Never believe a negative that has not been armed. Everything else is detail.

Two rules carry the whole workflow, and both exist because they were bought with real mistakes.

Cheapest-refutable-first. A sweep that starts with a web search and ends at the source has paid for the expensive step before asking the cheap question. The run this was built from went source-last and produced an artifact and two commits before anyone asked whether the behaviour was already known upstream. It was — for fourteen months.

Every null carries a control arm. A “not found” with no proof the probe could have found something is not a finding. It is a lead, and reporting it as a finding is how five false negatives reached a report in one session.

The gate every result passes through

A rung returning nothing is not an answer. It goes through the arm first, and what comes out the other side is labelled either a finding or a lead — never both, never neither.

The rule has a lane, and the lane is already installed

kb-adversarial-verifier exists to “try to REFUTE a claim by finding the probe that produces the opposite answer” — the gate above, executable. fable-orchestrator:premise-verifier is the sibling for a claim's unstated assumptions. Neither was named in the skill until today, which is the real finding of the tooling sweep: the gap was not a missing plugin. It was seven installed lanes nobody had written down.

How a tool should arrive

Four layers, each pinning the one above it. The rule that makes it work is that a tool does not enter the skill until its module exists and its test is green — because the failure this design exists to stop is adoption by paragraph, which has now happened twice.

Two traps in the plugin layer, both measured

Setting version PINS it. Push new commits without bumping the string and users stay on the cached copy. Omit it and Claude Code falls back to the git SHA. Never set it in both plugin.json and the marketplace entry — plugin.json silently wins.

The manifest is root-anchored. .claude-plugin/marketplace.json lives at a repository root and cannot be nested. A monorepo is still fine — git-subdir sources and --sparse cover it — but a relative ./plugins/x source breaks for anyone who adds the marketplace by direct URL.

What is not settled

This page describes a workflow, and four decisions inside it are open and are Ray's: what validated must mean before a tool ships; whether the wrapper is one module or four; whether the marketplace lives in this repo or its own; and whether it bundles just the tools or the skill with them.
