One decision · the integrity gate

The alarm and the empty room.

We deleted some valuable files, and we deleted the alarm that watched them. A cold reviewer says: you tore down the fence, not just emptied the paddock. Here is whether that matters.

The picture

A smoke alarm in a demolished room

You had a room full of expensive, irreplaceable things. On the ceiling was a smoke alarm that checked, every day, that nothing had been tampered with.

You emptied the room and knocked it down. The alarm came down with the walls.

Nobody disputes that. The reviewer's point is different, and sharper:

“One day you will build a new room, and put valuable things in it — and there will be no alarm, because you threw the alarm away with the old one.”
The load-bearing question

Is anything writing receipts today?

No. The path that wrote those receipts is the one we deleted. The surviving path hands the whole job to the graphify CLI and keeps no provider receipts of its own.

So the gate today would be watching an empty room. And this repo has a specific, measured opinion about that:

A gate that cannot fail is not a gate. Worse — a gate that sits permanently red teaches people to ignore gates, and then it costs you the next one too.

That is not hypothetical here. Had we kept it, it would have returned Rc.NOT_RUN with zero chunks to scan, and sat red on the ship path forever.

Three answers

What we can do

A · recommended

File an issue, ship as-is

Put the objection where the future builder will trip over it: whoever adds receipt caching to the CLI path has to answer "what guards these?" before merging.

Why this one: it keeps the warning without keeping a dead module. The risk is real but deferred, and so is the fix.

B

Keep the gate dormant

Restore the module, leave it out of the ship gates, repoint it at whatever the new path writes.

The cost: a module nothing calls, sitting next to the extraction code — which is exactly the "which path is live?" confusion this whole round existed to remove.

C

Out of scope

Guarding a feature nobody has built is speculative. Handle it when receipt caching actually exists.

The risk: nothing records the objection, so the person who builds it never hears it. That is how the gap actually happens.

A and C reach the same code today. The only difference is whether the warning survives — and that difference is the entire decision.

Worth saying plainly

The reviewer was right about the shape

It is easy to read "we deleted a gate" as carelessness. It wasn't — the gate and its subject went together, which is the coherent move. But Gemini spotted something neither the ruling nor I had said out loud: the evidence and the ability to check evidence are different assets, and only one of them had a reason to go.

That distinction is the finding. Whether it becomes an issue or a restored module is the smaller question.
