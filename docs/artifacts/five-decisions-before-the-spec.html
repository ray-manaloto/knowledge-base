Five Decisions Before the Spec

A cold lane read four prior reports and the design page, settled 11 questions it could answer from the repo, and left five that need you. Ranked by what a wrong answer costs.

Updated after publication — four of five now answered. 1 — enrollment first. 4 — the spec waits. 3 — dissolved by measurement, not decided: the “red gates” it worried about are green (2026-08-31). 5 — Ray’s call: “full” means every pin site, 35, not the 18 mapped. Only 2 is still open. Decision 2 also carries a finding that removes an option somebody proposed. 1

Does dependency population read mise.toml directly, or inherit the curated list?

StakesIf population still goes through a curated allowlist, the same seven tools that motivated the whole redesign stay invisible after the rewrite — a new engine built around the exact gap it was meant to close.

Options
  1. Auto-discover every dependency from mise.toml [tools], bypassing the curated list.
  2. Keep the allowlist; ship with the 7 gaps as tracked follow-up issues.
  3. Block slice 1 until every entry has an explicit row (delays MVP for mechanical enrollment).
Recommended: 1. All seven are already in mise.toml — I verified each one this session — so reading that table closes the gap at zero extra cost. One risk: some entries aren't things you want version-tracked. Mitigate with an exclude-list, so new tools are covered by default instead of invisible by default.
2

Where does new tracked state live — given the repo already breaks its own rule?

Confirmed live violation. do-not.md:70 says “Do NOT commit graphify-out/ beyond memory/” and :79 says “The rule is back to one exception.” I ran git ls-files graphify-out/ this session: it returns two directories — memory/ and an undocumented graphify-semantic-slice/ holding 5 tracked files. Two independent cold reports found it separately.

StakesAny new tracked artifact either extends a broken invariant, creates a third ungoverned subtree, or papers over a defect a future audit rediscovers.

Options
  1. Remove the subtree, restore one exception, then place new state elsewhere.
  2. Document it as a sanctioned second exception, then add the new state as a third.
  3. Put new tracked state outside graphify-out/ entirely and settle the subtree separately.
Corrected twice after publication. Read this, not my first answer. I first said “graphify documents no such structure”, from our fork’s README, pinned 2026-08-25. Checked against live upstream (v8 HEAD 33362d96, 2026-08-30, 0.9.53 vs our 0.9.50), that was wrong in the way that matters: upstream has a clear opinion, and it is the opposite of ours. Its README, verbatim: “graphify-out/ is meant to be committed to git so everyone on the team starts with a map.” The only recommended exclusions are cost.json (“local only”) and optionally cache/. Upstream has no derived-vs-retained distinction because it assumes you commit the whole tree. Control arm: the same grep returns 11 hits for a term known present, so the reads discriminate.

Why that flips the findingBy upstream’s convention, a tracked purpose-named subdirectory under graphify-out/ is exactly the right shape — graphify-semantic-slice/ is not misplaced. This repo inverts upstream’s default for one reason only: our graph is 737 MB, far past what git will carry. So the defect is not where the directory sits. It is that do-not.md still says “one exception” while the repo has two. The directory is undeclared, not misfiled.

And the multi-source concept is not a directory at all. What upstream ships is graphify global add/list/path, writing one flat ~/.graphify/global-graph.json outside every project — which do-not.md rule 2 already bans here as shared mutable machine state. The workspace/repository vocabulary is a hosted-server surface, not a local layout; control-armed against 19 upstream issues titled “workspace”, all of which mean monorepo workspaces and none a directory concept. No precedent to extend from either direction.

And the directory is messier than the question assumed graphify-out/ holds 13 entries, of which only 2 are tracked: memory/ (332 files) and graphify-semantic-slice/ (5). The other eleven are untracked leftovers — including graphify-semantic-corpus/ and two .superseded-* copies of it, from the layer this repo’s rules say was removed on 2026-08-24. All measured this session.

Recommendation, now revised by the evidence. The choice is no longer “where does it go” but which of two coherent stories this repo tells:

(a) Declare it. Amend do-not.md to name graphify-semantic-slice/ as a second sanctioned exception. This follows upstream’s shape — a purpose-named tracked subdirectory — and is the smaller diff. Cost: every exception makes the next one easier, and this rule has already gone stale once for a day.

(b) Move it to sources/extractions/. This repo already treats that as the tracked home for non-regenerable extraction output, and it restores a clean invariant: everything under graphify-out/ is derived and gitignored except memory/. Cost: it departs from upstream’s shape, and it is a move rather than a one-line rule edit.

I lean (b) — the confusion here has now happened twice, and both times the cause was tracked evidence living in a tree everyone reads as derived. But this is a judgment call about which story you want to maintain, not a fact the evidence settles.
3

Are the currently-RED gates a landing blocker for slice 1?

StakesThe design treats “gates pass” as the signal a bump is safe. If the baseline is already red for unrelated reasons, the protocol’s first real run fails on pre-existing defects — and reads as a failure of the new design.

Was: inherited, not re-measured. The hk-test 40-passed / 6-failed figure and the absent currency stamp came from a prior report. Nobody had re-run them. Superseded 2026-08-31 — kept for the record.
ANSWERED — by measurement, not judgement. mise run kb-gates at d08baaa7: all 7 rc=0, every row dirty:false — and the specific number was hk-test: 46 passed, 0 failed (floor 40). Note 40 + 6 = 46: the prior report saw the right test count and misattributed six of them as failures. There is no red baseline, so it blocks nothing.

The residual — kb-build IS red, but it is not one of the seven gates. Ray, 2026-08-31: it stays out (≈55 min, network, re-clones every pinned source; a transient DNS failure would become a blocked ship). A new seconds-long manifest-audit gate catches the same class before a build ever runs.

4

Does the spec wait for decision 1, or proceed on a stated assumption?

StakesThe design page’s “spec the full protocol now” call was made without ever reading the report that produces decision 1. Specifying first freezes the population contract — by the artifact’s own words, “the schema is the expensive thing to get wrong” — against whichever assumption the author happens to hold.

Recommended: wait. Decision 1 is one answer away and it is the cheapest possible moment to change it.
5

Should “full protocol” be redefined as “every mapped dependency”?

StakesA prior report refuted literal completeness as achievable, so the MVP’s success criterion cannot be met as written on day one regardless of how decision 1 goes — some legitimate gap always exists. Whoever writes acceptance criteria needs a definition of “full” a gate can actually check.

ANSWERED — Ray, 2026-08-31: every pin site. 35, not 18. “Full” means literally full. The denominator was re-derived this session and is 20 mise [tools] + 13 distinct pyproject packages = 33, of which 18 are covered by a reachable currency.toml [tool.X] table. Plus [tool.mise] and [tool.claude-code], which have neither a mise_key nor a python_package and so sit outside the 33 while being real tracked tools — hence 35.

The cost, accepted knowingly: the criterion reads 18/35 on day one and stays red until the 15 are mapped. That is a roadmap, not a defect — the alternative definitions all pass immediately by declaring the gap out of scope.

The uncovered 15, by name. mise (7): biome, gh, gitleaks, pkl, python, taplo, typos. pyproject (8): anthropic, httpx2, mcp2cli, msgspec, pytest, pytest-xdist, structlog, trafilatura. biome is on this list and is also the manifest currently breaking kb-build — the same gap seen from two sides.
