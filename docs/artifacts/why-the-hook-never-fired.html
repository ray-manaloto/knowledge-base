Why the hook never fired

It was never skipped. It refused to load — and said so out loud, in a place nothing was listening.

What broke

The hook file imported node:fs. A hook module may import only its own files and claude-code — nothing else. One line, and the whole module was turned away.

Why it looked silent

It wasn't. The engine wrote a real error — it just goes to the debug file, and last round didn't ask for one. Add --debug-file and the reason is right there in plain English.

Proof it works

Same command, one thing changed. Switch on → 39 hook events. Switch off → 0. The log even prints which of the two states you're in.

Switch can live here

Put it in the repo's own settings file and it works — checked with the switch removed from the environment entirely, and the hooks still ran. The plan you chose is buildable as you chose it.

It can say no

A hook can block a command outright, and the block holds even when permission checks are turned off. That is exactly the power the settings-file guard needs.
