The Research Spine

Two research engines already exist on this machine. One is /deep-research, a workflow baked into the Claude Code binary; the other is /antigravity:research, a command in a plugin. This page takes each apart, stage by stage, then draws the spine we would build out of them — with every tool, plugin, MCP server, skill and library named at the stage where it plugs in.

It is a command (commands/research.md), not a skill, and it delegates to the antigravity skill's "Deep-research recipe". The skill is explicit: "agy has no built-in Deep Research mode … so deep research is a Claude-orchestrated recipe, not a single agy call." Read from ~/.claude/plugins/cache/antigravity-for-claude-code/antigravity/0.23.0/ this session.

toolsagy-delegate (the plugin's bin) → the agy CLI (mise-pinned antigravity-cli 1.1.21) → Google web search grounding, and Vertex AI Search where configured. agy-cost-compare, agy-job (background), agy-doctor, agy-trace sit beside it.
tunable?Yes, per call. --tier flash | flash-lo | pro, or --model for any model agy models lists, and --effort. The skill warns that below agy 1.1.10 those flags were silently ignored in headless mode; 1.1.21 is past that floor.
reachable by an agent?Yes. The antigravity-delegate subagent exists for exactly this, and its only file-acting tool is the delegation wrapper.
caveats the skill itself statesprint mode uses search-summary tools and does not reliably fetch full pages, so citations are coarse, often domain-level; it can present parametric "knowledge" as a sourced fact; one agentic pass per call, so Claude re-dispatches to close gaps. Never ship its citations unverified.
budgetthe agy subscription is a scarce reserve here (your standing rule: one call maximum in a round unless stated). The savings claim is that bulky pages are read in cheap Gemini tokens and reach Claude as bullets.
worth copyingthe division of labour — Claude plans, verifies and writes; a cheaper lane does the bulk reading · step 3's "quote the sentence or reply NOT SUPPORTED", which is a per-claim primary-source arm · the ≥2-independent-domains rule.

The spine — one pipeline, both engines' best parts, our sources plugged in

Read it top to bottom. Red is what a person types (two entry points, Q2). Every white box in stage 1 is one adapter: it takes the scoped question and returns the same shape — URL, date, snippet, source kind — so stage 2 can dedup and rank them together. The grey stages are code, not agents. The teal stages are ours and can be routed to any lane (Claude, codex, agy) per call — the tunability /deep-research lacks.

where lychee sits — your comment e8af4040 on the synthesis nodeNot at synthesis. Twice, and both are cheap: gate 1 runs before any fetch, so a dead URL never spends a fetch, an extraction or three votes (measured today: 1,058 links in 34 s against 3 agent calls per claim); gate 2 runs on the finished report, so every citation a reader can click resolves. A third use is outside the spine entirely — mise run kb-links, the hk step this session added, which link-checks the repo's own docs and code.
the recency rule — your comment 92fe3e73It lives in stage 2, as a rank term, not a filter that deletes: every adapter that can return a date does (last30days, deps.dev, gh api's pushed_at, crates.io / PyPI upload dates, Firecrawl's index dates), and a tool or library nobody has touched in a year sinks below one touched last week. Today's worked case: the only PyO3 binding for lychee (jb--/lychpy) was last pushed 2023-09-26 — it ranks below lychee-bin 0.24.2, released weeks ago by the maintainers.

What the sweep found when the spine ran by hand today

The lychee-from-Python question was run through every stage-1 adapter you named, by hand, before this page was drawn — the full report with every null and its arm is at docs/research/reports/2026-08-27-lychee-from-python.md. The one-line answer: no maintained Python binding exists (#59 is an open wishlist item; jb--/lychpy died in 2023), the maintainers shipped lychee-bin 0.24.2 as the Python-side artifact instead, and the cheapest bridge is subprocess + --format json. Your ruling on that line (comment c4a5e3ea): "we have to build the python to rust binding using a modern framework library." So the subprocess bridge is the interim, and the binding is a build — the round-3 section below is which framework and where it lives. The recency rule decided it; the developer index and Exa found it; the graph, context7 and the research index confirmed they were the wrong instruments for it, each with a control arm.

The advisor's conditions — ratified 2026-08-27

fable-advisor, at the commitment boundaryThe spine stands, tiered, with four conditions it would refuse to ship without, and you adopted them: (1) the stage-1 record carries two more fields — every null its arm, every adapter its tier — so {url, date, snippet, kind} became {url, date, snippet, kind, tier, null-arm}; (2) vote independence is by source domain, not model family — three voters reading one page are one vote at 3× cost, and a single-domain claim stays unverified whatever the tally; (3) agy is never a routine voter (your one-call-per-round rule), so "≥ 2 families" means Claude + codex in practice; (4) the daily brief ships only after a per-run token cap exists. It also moved the first build: the adapter contract + gh-trackers adapter goes to codex-implementer first — its fixture is real (jdx/hk has issues disabled, and its structural zero must read as never asked) — and the binding spike second, with an exit criterion: name what subprocess + --format json cannot do.
