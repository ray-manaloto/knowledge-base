The shape of the thing

What is being built

One command upgrades every dependency in the repo. For each one it bumps the pin, runs the gates, and — if the gates go red — reverts that dependency and keeps going, reporting what it dropped. One commit per dependency, one pull request per batch.

The pin itself is never moved into a database. mise.toml and pyproject.toml stay the version truth. The database owns two things the files cannot express: which sources a dependency has to keep in sync, and how far along each dependency is.

The stage that costs subscription tokens — semantic extraction — is recorded as deliberately skipped, so a full upgrade can run at zero token cost when the budget is tight.

Architecture

Three components, and the one arrow that matters

Answering a reader question

Where the status actually lives

Not in a column on the dependency. Status is a second table with one row per dependency per stage — which is the only shape that lets “the gates passed” and “the expensive stage was skipped for budget” be true about the same dependency at the same time.

Correction: an earlier version of this section called those stages “deliberately skipped”, as though skipping were the design’s default. It is not. skipped_tokens is an option you exercise when the token budget is tight — the stages run normally otherwise.

Question A · already answered, this session

The schema had its arrow pointing the wrong way

The original two-table design put a syncs_manifest column on the dependency row, justified by a measurement: only 2 dependencies today own more than one manifest. The advisor was asked to re-check that, and refuted it — then a cold reader refuted the refutation, harder.

Correction · this section was wrong when first published

The first version of this page said a second manifest per dependency was a future problem — “the moment a second is built, this breaks.” That was wrong. It is already built. codex owns two manifests today, and the figure below now shows the real pair instead of a hypothetical one. Both were read directly, not taken from a report.

The second finding, which is bigger than the schema

The two manifests advance on different clocks. Bumping codex from one release tag to the next says nothing about whether the docs mirror moved, because the docs mirror does not follow releases at all — it follows another project’s branch head.

So source_synced is not one stage. It either means “the code manifest matches the pin” or “every mapped source advanced to its own upstream”, and those are different builds. That question is now on the list below.

Added requirement

The documentation should be generated too

The same disease that the upgrade protocol fixes in pins is already loose in the prose. CLAUDE.md says graphifyy[all]==0.9.48. pyproject.toml says 0.9.50. Both were read today. Nothing generated would drift like that.

So: any document that restates a fact whose authoritative copy is machine-readable — a version, a count, a status, a dependency list — stops being hand-maintained. Judgment stays hand-written; restatement does not.

That test has a sharp edge, and the advisor put the edge in a place worth drawing.

Two exclusions that make this safe

sources/** and docs/direction/** are never regenerated. A source manifest records what a source said at ingestion time, and the direction files are your words verbatim — a generator that “fixed” either would destroy the provenance they exist to hold. The scrape lane carries that exclusion list explicitly.

And a number written with its condition — “772 MB, measured 2026-08-23, this figure goes stale” — is reported separately rather than regenerated. Refreshing the number and dropping the caveat makes the doc worse.

The generated-docs answer

The scope is smaller than it sounds

Of 936 tracked markdown documents, 33 restate a machine-readable fact. Thirteen of those are already generated — almost all the graphify skill tree, which the repo regenerates on every version bump. That leaves 19 hand-written and 1 mixed, and only 8 are drifted right now.

And the advisor’s treatment split held under contact: 16 of the 20 want a drift gate, not a generator. Only 4 want a generated region. Nothing wants whole-file generation, because every candidate carries prose.

The tooling answer, and it corrects the advisor

The advisor guessed Jinja2 was already in the dependency closure. It is importable but ambient — uv tree --invert --package jinja2 resolves 166 packages and prints no Jinja2 node. Control arm: msgspec resolves and is declared; a bogus module is MODULE_NOT_FOUND. So adopting it adds a declared dependency.

It would at least consolidate rather than duplicate: currency/report.py already hand-builds markdown in four places (:41-51, :139-145, :357-413, :422-438).

A requirement I dropped

The states are a state machine, and they are generated

Your comment, verbatim: “i had required to use a modern state machine library w enum states that are code generated”. That is not in #638 anywhere, and it is not in anything I wrote today. It changes the second table from a design choice into a constrained one.

It also reconnects to an answer already on the record. Round 1’s Q4 said codegen covers all five, and one of the five was the status record. So dep_stage.state was never meant to be a hand-typed string column — the enum is generated, and a library owns which transitions are legal.

What this rules out, immediately

A hand-written CHECK (state IN (...)) constraint, a Python StrEnum typed by hand, and any “the code just writes the right string” approach. It also means an illegal transition — reverted straight to ok, say — becomes a library error rather than a bug nobody notices, which is the whole reason to want one.

And the generator already exists here: datamodel-code-generator is pinned in its own isolated group and mise run kb-codegen drives it. This is the tool that would have caught the two hand-written parsers that returned false answers.

What is not settled by your comment is which library, and that is an architect call rather than a question for you — unless you already have one in mind, in which case say so and it is settled. The shortlist is small and the trade is about whether transitions are declared in Python or in a schema the generator reads.
