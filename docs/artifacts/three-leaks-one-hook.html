Three Leaks, One Hook

The plugin never installed itself here. Once installed by hand, its SessionStart hook pulled 8.3 GB of your own tools into the plugin's data dir and still failed. Three walls the hook builds do not hold on a real host — and every one of them holds in a container, which is why the container test alone would have said "green".

Why it was not installed at all

The house analogy: putting a plugin's name in the project's .claude/settings.json is like writing a guest on the invitation list. Since Claude Code 2.1.195 that no longer opens the door — the guest must be walked in with claude plugin install. Marketplace ray-manaloto was not even registered on this machine.

sources/claude-code-docs/…/discover-plugins.md:486 · fix = the README's own two commands, run this session: marketplace add → plugin install (+4 dependencies), scope: user

Why the container would have lied

Leak 1 · home config

A container has no ~/.config/mise/config.toml. Nothing to walk into.

sources/mise/docs/configuration.md:15 — .config/mise/config.toml is a hierarchy filename

Leak 2 · the git shim

A container has no ~/.local/share/mise/shims on PATH; git is /usr/bin/git. The untrusted checkout is never consulted.

mise verbose: "Config files in …/checkouts/…/mise.toml are not trusted"

Leak 3 · activation

A container shell is not mise activated, so __MISE_DIFF is unset and mise exec builds PATH from scratch.

armed: mise bin-paths lists both dirs; exec's PATH had neither

So slice 3 is two things, not one: the container acceptance test Ray asked for, and these three fixes in the hook and wrappers — otherwise the test passes over a plugin that breaks on the one machine that matters.

What slice 3 must contain

  1. Hook + both wrappers share one environment. Today the wrapper does not even carry the hook's confinement — invoking it re-leaked the home config and started a Rust install. One shim (bin/mise-env) that sets ceiling, trust, data dir, uv cache and unsets __MISE_*; hook and wrappers call it.
  2. Container CI in the marketplace repo (it has no .github/ today): mise oci build on ubuntu-latest, then a job that runs the README's install commands, the hook, and aggregated-research trackers ….
  3. One human step only you can do: claude setup-token → gh secret set CLAUDE_CODE_OAUTH_TOKEN -R ray-manaloto/claude-code-marketplace. The repo has zero secrets today; the install job needs none, the agent job needs this one.
  4. Host regression arms stay in the docs: the three probes above, so a future hook change is armed against a real host, not only the container.
