Three Switches Before the Plan

The plugin is installed and live. But its default setting does the one thing you installed it to prevent — it re-injects the plan into context on every matched tool call — every Write, Edit, Bash, Read, Glob and Grep. Three switches decide whether it saves context or spends it. Here is what each one actually changes.

Corrected after publication — 2026-08-30, later the same day

The per-call cost is about 5× what this page originally said. The first version quoted the plugin's own ~90 tokens per matched tool call. That figure is measured against the plugin's short starter template. Measured against our actual plan: head -30 task_plan.md is 1,748 bytes ≈ 440 tokens. At 500 tool calls that is roughly 220,000 tokens — about 22% of a 1M window, paid on every turn.

And the framing was wrong in a way that matters more than the number. The original page argued autonomous mode on token cost alone. The sharper argument is below, in What the injection mode does and does not fix: the problem this plugin was installed to solve is cross-session loss, and the injection mode has nothing to do with that. The recommendation is unchanged; the reason for it is better.

The mechanism: two taps into your context

The plugin reads your plan file and pours it into the model's context through hooks. There are two places it pours, and one place it can refuse to let a turn end.

The irony of the default

You installed this because "we are losing too much information." Legacy mode's fix for that is to repeat the plan into context on every matched file operation — which spends context to save context. On a heavy session that is a net loss. Measured on this session: 55 matched calls in the first hour.

What the injection mode does and does not fix

This is the distinction the first version of this page missed, and it settles the choice more cleanly than any token count.

FailureWhat actually rescues youDoes the mode matter?
Losing state across a /clear — the stated reason for installing this The files existing on disk. The SessionStart hook fires on clear and the skill's first instruction is to read all three files. No — identical in every mode
Losing state to compaction Same files. PreCompact fires in every mode and reminds the agent to flush first. No — identical in every mode
Drifting off-plan mid-turn, 200 tool calls deep Re-injection — the plan staying in the attention window. Yes — this is the only thing the mode changes

So the mode is a bet about intra-session drift on a strong model, priced at ~440 tokens per matched tool call. It is not the mechanism that protects you across a /clear — the files are, and they are there either way.

One honest cost of autonomous mode, stated because the first version of this page did not. Legacy injects the raw tail of progress.md — actual sentences. Autonomous replaces that with a synthesized ledger block that reports counts and the last event type, not text. So in autonomous mode nothing from progress.md reaches context on its own; it has to be read deliberately. That is a real narrowing, and it is the one place the default is genuinely richer.

The add-on worth taking with it: inject-smart

The default injection is head -50 — position-blind. Late in a long plan, the in-progress phase, the decisions journal and the error table all sit past line 50, so you pay the tokens for a window that no longer contains the active work. The inject-smart token in .mode swaps that for goal, next step, current phase, the full in-progress phase, and the last three decisions. It composes with any mode.

Recommendation — autonomous, plus inject-smart

Autonomous closes the expensive tap and turns attestation on, and its Stop hook stays advisory — so nothing can refuse to end your turn. Gated buys one thing on top: a hook that forces continuation until the plan reports complete. That is valuable for an unattended overnight run and is a liability in an interactive session where you want to stop and steer.

Gated is the switch to flip later, on a specific long run, not the one to start with.

Recommendation — slug mode

One ignorable directory instead of three loose files in a repo root that is already carefully curated. It also makes the archive step — the thing that stops a finished plan from haunting the next session — a single directory move.

The .gitignore call I will make unless you say otherwise: add .planning/ to .gitignore. This repo's convention is that live working state is gitignored and durable records are tracked; the durable record of a round is already the handoff, the artifacts and kb-remember. A live plan is working state.

The trap that fires either way

Whatever you pick: a finished plan re-injects itself into the next session, forever. The moment this plan exists, every new session's UserPromptSubmit pours it back in — including after this round is over, when it will contradict whatever next-ticket generates.

The fix is one step at the end of the round, and it is now owed: archive the plan directory when the round closes. That step belongs in clear-prep, not in anyone's memory.
