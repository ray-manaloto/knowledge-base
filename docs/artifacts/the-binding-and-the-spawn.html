Reading: the CLI's cost is per FAILED url (~54 ms each above the 200 baseline; cause not established — HEAD→GET fallback is the unmeasured candidate). On localhost the binding is 10–80× faster per URL. hk's real check is network-bound (100 ms+ remote round-trips), where 23 ms of CLI overhead is a fraction, not a multiple — that case was not measured. The structural difference that survives: the CLI dedups and retries; the binding hands you raw per-URL awaits and leaves both to you.

The choice

AStop here — the spawn stays

hk already runs the CLI; --format json carries every fact the binding returned. The spike's own exit criterion ("or 'nothing', which ends the binding") is met as measured. Cost: zero. Risk: if a future adapter wants per-URL streaming or a typed Status, this is re-opened.

BBuild the binding in its own repo

Your round-3 ruling: PyO3 0.29 + maturin 1.15, asyncio-native, own repo after a spike here. The spike passed its two soundness questions. Cost: a Rust toolchain in that repo's CI, a wheel to publish and re-pin, lychee-lib's tree to track. Risk: Windows teardown unmeasured.

CMeasure first, decide after

One more spike run: N URLs through one CLI spawn vs N await check() calls, timed. Turns the "not measured" cell above into a number before B's cost is committed. Cost: ~30 min on this host. Answers whether the binding buys speed — the one thing the spawn structurally cannot give per-URL.
