The Funnel Gate

This repo exists so research becomes corpus. A round convened to fix that produced 33 research files and zero lines of corpus — so the rule now has teeth: a branch that researches and never funnels cannot ship.

Five clauses describe what this project is for. Until today, none of them had a mechanism — they were prose, and prose is advisory. The measurement that forced the change is uncomfortable and simple: the branch that was about the funnel problem did not funnel.

How it decides

Four questions, five outcomes. The fifth exists so "we could not check" can never wear the colour of "clean".

Deleting a research file is not producing research, so only added and modified files reach question two. And a sources/REGISTRY.md edit counts as funnelling — research that touched no repository can still record what it learned.

Why the fifth state exists

A gate has two obvious answers and one dangerous one. If the git call fails — a detached HEAD, no main, not a repository — the honest answer is we never asked the question, and this repo has paid before for collapsing that into "fine".

So the code keeps two empties apart that most code merges: None means the git command failed, () means it ran and found nothing. One becomes no_base and exits 127; the other becomes clean and exits 0. They are never the same value.

The ledger is the mechanism

Eighteen rows record a tool we will not use. That looks like waste and is the opposite: the next session asking "did we already try pyan3?" now gets an answer instead of re-running the evaluation. Every verdict is quoted verbatim, not paraphrased — this survey's headline finding is a rejection whose stated reason was later contradicted by measurement, and that was only discoverable because the reason had been quoted rather than summarised.

What this does not do

Three limits, stated because a gate that overstates itself is worse than none.

Pinned is not ingested

The corpus build is currently failing — a detect preflight error across six sources — so the eight new pins are registered and not extracted. Every new row's status reads manifest, never code. A registry that claimed an ingestion that did not happen would be worse than one with fewer rows.

It counts files, not value

A one-line touch of REGISTRY.md satisfies the gate as fully as eight pins do. This is deliberate — the alternative is a gate that judges quality, which it cannot do — but it means the gate raises the floor rather than guaranteeing the work was good.

It watches two directories

Only docs/research/** and docs/artifacts/**. Research that lands anywhere else is invisible to it. That is a known bound, not an oversight — but it is a bound, and a probe's bound is the first thing to check when it says everything is fine.
