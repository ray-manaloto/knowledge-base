THREAD 3efb4767 — "semantic versioning for both the plugin and cli"

We already have a versioning scheme. It just isn't semver.

Neither manifest carries a version, and that is a documented mode, not an omission.

factconsequence
version is the update cache keyClaude Code skips an update when it matches what's installed, and the version literally names the cache directory.
no version anywhere → falls to the source commit SHAWe are on the commit-SHA scheme today. Users get an update on every marketplace commit.
the docs name that scheme's best fit"Internal or team plugins under active development" — which is exactly what this is.
explicit semver flips the modelUsers then update only when you bump. Forget a bump and everyone freezes on the old plugin while your commits land invisibly.

So this is a real choice, not a gap to fill. Semver is right once someone other than you installs this and expects stability. Until then, commit-SHA gives you an update on every push for free. The CLI is different — a published package genuinely needs semver, because a mise.toml pin has nothing else to name.

THREAD 58e866cd — "renovate and dependabot gha workflow, similar to dotfiles"

Copying dotfiles means copying three mechanisms, not one

mechanismwhat it covers
Renovate (hosted Mend app)205-line config, 8 managers, 8 custom regex managers. Nothing runs it — it is the hosted app; four workflows only react to its PRs.
Dependabotpip only, scoped to /python. Deliberately excludes GitHub Actions, because Renovate owns those — both would race.
a daily lock-refresh workflowThe one that matters here. Renovate's native mise manager only rewrites version strings — it can never run mise lock. A separate cron job regenerates the lockfiles and auto-merges.

Two traps recorded in dotfiles' own config, both mise-specific. Renovate's native mise manager silently ignores [bootstrap.packages] — its schema parses only tools/tasks. And mise's registry version strings can disagree with a GitHub tag, so the manager writes whatever the datasource says.

Neither knowledge-base nor the marketplace repo has any of this today. The marketplace repo does have CI, so it is the one that can actually host it.
