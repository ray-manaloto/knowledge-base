The Lever Is the Wrong Size

I asked you to choose between registering one file and excluding it. That was not the choice. The problem is one file; the exclusion lever is one whole source. Nothing balances.

Correcting my own framing first. I wrote that “registering it approves a zero-node file into the corpus and excluding it drops a source you're currently tracking” — phrased as two comparable costs. It isn't.

build is a field of Manifest, not of a file (manifest.py, _EXCLUDED_BUILDS = frozenset({"skip", "defer"})). There is no per-file exclusion. The smallest available "exclude" is the entire uv source: 638 Rust files — to avoid registering a 3-line test fixture.

Why this is not even a new decision

uv already has three of these, and two are the same shape

_EXPECTED_METADATA_ONLY already carries three uv entries, every one with the disposition reviewed-package-manifest-no-name:

relative pathshape
Cargo.tomlbare [workspace] root
test/workspaces/albatross-groups-only/pyproject.tomla pyproject fixture with no name
test/workspaces/albatross-virtual-workspace/pyproject.tomla pyproject fixture with no name
crates/uv/pyproject.tomla pyproject fixture with no name — the fourth

The two middle rows are the same case as the new one. Registering it is the fourth instance of a pattern this repo settled long ago, not a precedent being set.

The thing that made me doubt it

“Approving a zero-node file” sounds like laundering a defect. Here it isn't.

The worry is real and this repo has written it down: a registry entry can be used to launder a genuine extraction regression — approve the loss, and every gate goes green over it. That is why registration demands a reviewed hash and a stated disposition, and why the audit gate's own scope explicitly excludes registry truth.

What makes this case different is what the file actually is:

# Integration tests run uv from this crate and exercise source builds.
[tool.uv]
no-build = false

There is nothing to lose. It has no name, declares no package, and carries no symbols — zero nodes is the correct extraction, not a degraded one. Registering it records a true fact. biome:Cargo.toml is the same story: a bare [workspace] root whose members are the crates that do extract.

Recommendation: register both. One row each, with a real hash and the current pin. A codex lane is doing it now, told explicitly to dissent rather than reach for build = skip — manifest.py already warns in its own comments that a silent exclusion is “a way to make a red build green by dropping the source that was telling the truth”.

Overriding this is still yours, and the honest form of the override is: is astral-sh/uv worth keeping in the corpus at all? That is a real question with a real answer either way — but it is a question about 638 files, and it should not be decided by a 3-line fixture.
