Where verification sits, and how the chain runs itself

Verification is in-session, and the numbers say it fits. Container acceptance returns an exit code and a few extracted lines, not logs. A cold review report is 5–15K tokens; two rounds is ~30K worst case. Because implementation happens in the lane, the architect session has room for the receipt before the handoff. A ticket ends verified: receipt for HEAD, acceptance green, then handoff.

The escape hatch. When a second review round does not converge — this repo's measured pattern, where fix rounds breed their own findings — the session closes with a handoff naming a fix ticket rather than burning past budget. A fix round earns its own cold pass anyway, so this costs nothing.

#574 is what makes the rest run unattended. A tracked chain file is the ordering, the tracker is the status, and a task prints the first ticket whose blockers are all closed. The handoff's next-task line becomes that output verbatim. When nothing is ready it names the open blockers; when the tracker cannot be reached it says so and never guesses.
