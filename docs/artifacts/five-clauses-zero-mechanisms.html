Two things settled today

Resolved — #524 needed no fork change

The blocker on your immediate step was framed as "graphify has no honest _origin tier for derived nodes". True of graphify's vocabulary — and irrelevant, because graphify never checks the vocabulary:

graphify build.py:48-50    o = item.get("_origin")
                           if o is not None: return o == "ast"

kb_setup  prose.py:97-99   def is_ast(n): return n.get("_origin") == "ast"
                    :162   kept = [n for n in nodes if not is_ast(n)]

Both are a pure inequality against one literal. No enum, no allowlist. A node stamped _origin = "derived" is trusted because present, is not "ast", and survives both filters — on the pinned graphify, with zero fork delta. The only thing rejecting it is our own validator at chunks.py:181. Widening that is a small change in this repo, which is exactly where you want the work.

That's the third time this round I read a thing's shape instead of its text — after the "6 invariant-banned verbs" and "project-Claude-only". It's a pattern now, not an incident.

Build order — and why guards land last

My first draft wired the guard first. That was wrong: a guard that denies on session-state before the index exists blocks the first web action of every session, including the ones where the corpus genuinely has nothing. Maximum annoyance, minimum discrimination.

The layer that decides everything — 3b

The advisor caught a hole that would have made all of this decorative. My guard unlocked after one graph query per session. So: run one kb-query at startup, then fetch freely and store nothing. Layer 2 ended in "prints the next command" — prose again. Layer 3 only fires on URLs that were stored. Nothing detected a fetch that never became a source.

The cause: I copied graph_first's shape without checking the semantics fit. Orientation is once-per-session. Ingestion is per-fetch. So the hook now logs every allowed fetch, and at session end URLs fetched − URLs in the corpus must be empty.
