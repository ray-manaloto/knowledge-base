The three that stop the ship

All three live in graphify_native_extract.py — the newest, largest, and least-exercised code on the branch. Each is shown as the mechanism that produces it, then the probe that made it happen.

Blocking Armed

A mistyped preview silently becomes a real extraction

python/src/kb_setup/graphify_native_extract.py:253–264

The argument parser reads --out and takes whatever token follows as its value. It never asks whether that token is itself a flag. So --out --dry-run does not fail, and does not warn: it quietly assigns the string --dry-run as the output directory, steps the cursor past both tokens, and leaves dry_run at its default of False.

The user asked for a preview. What runs is the real thing — a token-spending, disk-writing extraction, into a directory named after the flag they were trying to use.

The arm — run against the real parser, with a control

['--out', '--dry-run']     -> dry_run=False  out='/repo/--dry-run'
['--model', '--dry-run']   -> dry_run=False  model='--dry-run'
['--dry-run']              -> dry_run=True   (control: probe discriminates)
Blocking Armed

The output guard checks one door and leaves the other open

graphify_native_extract.py:359–370 · graphify_env.py · graphify/paths.py:26

_refuse_out exists to stop the extraction writing somewhere it must not. It validates opts.out — the value of the --out flag. But --out is not the only way to move graphify's output root.

Graphify reads GRAPHIFY_OUT from the environment at import time, by design, for worktree and shared-output setups. clean_env() strips every non-Claude backend trigger — and passes GRAPHIFY_OUT straight through. So an inherited environment variable relocates the output root without ever meeting the guard.

The arm — end to end, both halves

clean_env passes it through   -> GRAPHIFY_OUT = /tmp/pwned
graphify default             -> paths.GRAPHIFY_OUT = graphify-out   (control)
graphify with the env var    -> paths.GRAPHIFY_OUT = /tmp/pwned
Blocking Armed

The only code that actually runs graphify is untested

graphify_native_extract.py:446–454, 495–508 · tests/test_graphify_native_extract.py

Forty-two tests cover this module, and they are green. Every one of them exercises the --dry-run short-circuit — the branch that prints what would happen and returns. _run_real and _run_cluster, the two functions that spawn the subprocess, spend the tokens and write the disk, are reached by none of them.

This is not inferred from reading the tests. It was measured by deleting the functions' bodies.

One finding I generated and then killed rather than report. A line in artifacts.py reads except OSError, json.JSONDecodeError: — no parentheses, a Python-2 syntax error. Byte-level probes agreed: length 41, zero parentheses. But the file imports and the AST parses.

Two probes disagreeing means one is broken, and it was mine. This is PEP 758, new in Python 3.14: unparenthesized except tuples are valid. The interpreter here is 3.14.7, requires-python is >=3.14, and there are 69 such clauses across kb_setup — house style, not a defect.

The lane that had to be re-run

Batch A — the 1,155 lines of brand-new extraction code — came back from the first lane as a four-bullet paragraph with zero citations, closing with “the code is robust and functions as described.”

It had been told nothing about what the change was for. “As described” is the happy-path confirmation a cold lane exists to break, so the report was rejected rather than counted. Re-dispatched to codex — cross-family, since all three commits touching that file are Claude-authored — it returned six findings, every one cited, including all three blockers above.

The two reports covered the same 1,155 lines. The difference was entirely in whether citations were demanded.

Round 1 of a two-round bound. Reports persisted verbatim at .agent/kb/review/reports/review-fa4ed551…-cold.md. No receipt is written while blocking findings stand — kb-review-receipt refuses --blocking > 0 before writing anything, so an unfixed branch leaves the same empty disk as an unreviewed one, and the lane reports are what tell the two apart.
