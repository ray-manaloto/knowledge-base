A decision that is yours, not mine

The Sixth Argument

A linter allows a function five arguments. The new feature made it six. Nothing is broken — the only question is which kind of cost you would rather pay.

I'm asking because this repo's own rule says so: no ignore rule without explicit user approval. The implementing lane added one and flagged it rather than quietly shipping it — which is the correct behaviour, and why it's in front of you.

What the function actually is

It is the currency engine's single judgment call: given everything known about a tool, may a version bump apply itself without a human? Each argument is one independent fact a gate reads.

Why the honest answer isn't obvious

The rule that makes this your call

zero-skip-policy rule 1: never add an ignore rule without explicit user approval; each suppression must be justified with a documented reason. Rule 5 adds: a passing gate with suppressed warnings is not "green".

The lane satisfied the documented reason half and stopped at the approval half. That is the rule working. But notice the tension the rule itself sets up — approving this makes the gate green in a way rule 5 explicitly says is not the same as clean.

The case against approving, stated fairly: a per-file ignore is permanent and file-wide. It does not say "decide() may have six" — it says "nothing in decide.py is ever checked for this again." If a future function in that file grows to nine arguments, nothing complains.

The case for: the refactor does not remove information, it renames it. Six facts go in either way. And the churn lands on the one test suite you least want mechanically rewritten to satisfy a threshold — the suite guarding whether a bump may apply itself unattended.

There is a third option neither pan shows, and it is worth knowing about before you choose: ruff's max-args is configurable, and this repo has never set it — the 5 is simply ruff's default. Raising it to 6 project-wide would need no per-file ignore at all, but it relaxes the check everywhere, which is a wider blast radius than a single named file.
