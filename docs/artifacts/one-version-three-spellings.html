One version,
three spellings

A routine bump of four pinned tools. The version number was correct every time. It was written down wrong anyway — and each of the three places it goes wants it spelled differently.

The thing that goes wrong

A tool has one version. But that version lives in three files, and each file has its own idea of what a version looks like. Get the number right and the spelling wrong, and everything still reads green.

measured mise ls hk reported v1.56.1 (missing). Every version mise had ever installed was bare — 1.48.0, 1.52.0, 1.54.1 — which is the control arm: the probe can report a resolving pin, and for this one it did not. Anyone pulling that commit gets a mise run lint that cannot find hk.

The trap underneath it

Fixing the spelling means asking git what a tag points at. That question has two different answers, and the command most people reach for hides which one you got.

caught The control arm was accidental and decisive: re-reading the current tag first. v0.49.0 came back as dc388699… while the manifest already held b0401135…. Two values for a pin nobody had changed — so the command, not the file, was wrong.

The third failure: the number moved, the record didn't

Nothing was misspelled here. The pin was simply updated in one file and not the other — by following the documented workaround for a known bug.

What the register actually covers

The sweep's incidental finding, and the larger one. Of seventeen tracked tools, only four carry a reviewed expected version at all — and roughly the same number again are pinned with no record anywhere.

Corrected after publication

The original figure was miscounted from an intermediate listing rather than counted from the file. Corrected 2026-08-25; the tally above now reads 5, and no other figure on this page changed.
