The two events that would move this

Nothing else does. Neither is a schedule — both are things that happen upstream, so the mechanism has to be a watch, not a reminder.

A newer upstream release lands

→ rebase the fork

Upstream shipped 15 releases in 15 days when last measured, so this is the likely one. The fork branch is replanted onto the new tag, pushed, and the commit is moved in every surface above in one commit.

#2981 merges and ships to PyPI

→ retire the fork entirely

  1. Revert pyproject.toml to an ordinary == PyPI pin.
  2. Point the manifest back at Graphify-Labs at the matching tag.
  3. Delete the [tool.graphify.fork] block.

Neither event notifies us. There is currently no command that records a watch item as re-probed — that gap is filed as issue #486, and it is the same gap that blocked five reviewed dependency bumps from landing last round.

What the rebuild actually hit

Unrelated to the fork, but it ran in the same session and the distinction matters: this is not the failure the build stamp predicted.

Detect preflight failed on 6 of 84 sources — no artifact written

The stamp predicted an IncompleteGraphifyOperationError from a pruned-nodes condition. What happened instead was a failure one stage earlier, in detect, on six of the eight manifests added last round:

  • unclassified-files (5) — biome (21 unresolved: licence files, .ungram, .grit), gh (15: CodeQL .ql/.qhelp, embed placeholders), ctx7 (1: .mcpb), firecrawl-cli (1: a husky hook), trafilatura (1: a .dtd).
  • timeout (1) — ffmpeg exceeded the detect budget.

Because it failed closed, no aggregate artifact and no stamp were mutated. The graph is exactly as it was, and provenance is still absent — .currency-stamp.json and .compose-manifest.json both still do not exist.
