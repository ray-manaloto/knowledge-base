The Rule That Never Loaded

Progressive disclosure works here — an ~86% saving where it fires. It is also measurably unreliable: one scoped rule loaded in 0 of 684 real requests, because of how this repo is told to read files.

This was raised before. Issue #492 is open and carries your framing, with #218 as its budget half and #117 as the earliest statement. Nothing here is new ground — what follows is what the repo already measured, so the design starts from evidence rather than from the idea.

The mechanism you would reach for first is the wrong one

Injecting rules through hooks looks ideal — fire on the event, pay nothing otherwise. Two documented facts kill it for rules. Text framed as an out-of-band system instruction can trip Claude's prompt-injection defences, so a rule-shaped injection is surfaced to you rather than obeyed. And the docs steer away explicitly: "For instructions that never change, prefer CLAUDE.md."

Hooks are for facts that change per event. Rules are not that.

What this leaves

The saving is real and the repo has already proven the pattern on itself: auto-memory is 310 topic files, 758,902 bytes, 97% unloaded, pulled on demand. That design has simply never been applied to the 137 KB of rules that load every session — which is #492's own work item 5.

Three constraints shape any move:

  • Every lazy mechanism is one-way. Zero until triggered, then resident. There is no unload. So laziness reduces the floor, not the ceiling of a long session.
  • Behaviour-triggered rules cannot be scoped at all. The repo's own taxonomy: a rule that fires when a warning is about to be dismissed, or when validation is about to run, has no file to hang a glob on. Scoping those makes them absent exactly when needed — which has already happened twice here.
  • Validate every glob against telemetry. `0 / 684` was invisible until raw request bodies were captured. A glob that looks right and fires never is worse than an eager rule, because it reads as a saving.

One thing has to come first

#214: md_budget counts only what is in the git index. Move text out of eager context before fixing that and the budget will report an improvement it cannot actually see — a false green on the very instrument you would use to judge the change.
