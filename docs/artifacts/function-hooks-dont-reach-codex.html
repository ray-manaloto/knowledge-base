Function hooks don't reach codex

You asked that both families follow the new direction. Only one of them can run it — and the guards that bind both are the Python we'd be replacing.

What it means

Rewriting the 12 guards in TypeScript doesn't move them — it duplicates them. Codex still needs the Python, so we'd maintain the same rule twice, in two languages, with no shared test. And when a shell-command check drifts, it drifts silently: something slips through and nothing says so.

The way out

Keep one implementation. Make the new hook a thin shell that calls the Python you already have and trust. You still get everything the new mechanism buys — knowing who's calling, worktree awareness, refusals the model can read — without a second copy of the rules.

A count to fix

Of the 13 don't-do-this rules, 3 are already enforced, 1 can't be checked by any machine, and 7 are the real target. A plan for 13 is a plan for 6 that can't be delivered.

One free win

"Don't commit to the main branch" is enforced today only when you push — its own text admits the commit still lands. Moving that one is a genuine upgrade, not a port.
