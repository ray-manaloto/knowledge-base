It measures where the digits sit, not how risky the release is

Gate 1 lets a version update apply itself only when the last number moved. Run it over the four upgrades actually in front of us and it disagrees with itself — same kind of release, opposite answers.

The two highlighted rows are the same event. mise passes only because its date-based numbering puts the release in the last slot.

And a "no" here can never be turned into a "yes". The other gate that stops you — an open issue upstream — has a way to record that you looked and decided to go ahead. This one has none.

So the refusal message telling you to "resolve them via the interview first" points at a door that was never built. That is why the codex bump had to be done by hand today.

→ Three ways to go, and I'd drop it. Remove it · or give it a way to be cleared, like the issue gate has · or narrow it so only a real major version stops. The four remaining gates already read the release notes for breaking changes, which is the thing this one was standing in for.
