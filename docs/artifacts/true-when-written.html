A live guard hole, confirmed while checking the survey

The survey claimed hook_guard misses a path-qualified graphify. I ran it rather than believing it — and it is worse than reported:

CommandVerdict today
graphify extract .denied
./.venv/bin/graphify extract .allowed
uv run graphify extract .allowed — a second spelling the survey did not name

The survey justified its finding by saying settings.json uses the ./.venv/bin/ spelling three times. That part is false — grep -c returns 0. The hole is real; the argument for how likely anyone is to walk into it was not. Both facts are worth carrying: a true finding can arrive with false supporting evidence, and only checking separates them.

What to add, ranked

  1. Refuse a merge when local is ahead of the PR head. Catches instance 1 exactly. Belongs in pr.py, not a git hook — a hook is per-worktree and would run under each of seven stale worktrees. Already specced and in implementation. Falsely flags a branch you deliberately moved past; the right answer there is a loud refusal you override on purpose.
  2. A currency probe for absolute paths in effective git config. Catches instance 2 exactly, and costs no new machinery: kb-currency-check already runs at SessionStart, offline, ~10ms, and its whole job is "true when written, false now". False-positive cost is near zero because that task always exits 0 and can never gate.
  3. Deny writes to sacred out-of-repo paths. The invariant against touching ~/.claude, ~/.gitconfig and friends has zero enforcement today. A deny-list, never an allow-list — an allow-list would block the scratchpad, the sibling dotfiles repo, and every worktree, and every measured guard defect here has been a false positive rather than evasion.
  4. Close the path-qualified graphify hole — and the uv run spelling with it. Confirmed above.
  5. Enable hk's no_commit_to_branch. One line. The don't-commit-to-main invariant is prose-only today, and hk ships this builtin with its own pass/fail tests.
  6. Track the 16 plugins for currency. In a repo whose invariant is reproducible inputs and which pins ~84 corpus sources to a SHA, sixteen third-party plugins execute untracked.

What NOT to add

  • An hk pre-push stage. It is the biggest coverage gap and still the wrong fix: a git hook is per-worktree, so it would run under the config of each stale worktree — the very staleness this survey is about. One copy in pr.py governs them all.
  • A link checker as a blocking step. Right idea, wrong gate. Network-bound and rate-limited, so a transient becomes a red pre-commit — the exact misreading this repo has a rule against. Adopt it as a reporting task or not at all.
  • A blanket "no absolute paths in config" lint. Absolute paths are correct here by design. The narrow question — does the referenced path still exist — is the one worth asking.
  • Budgeting the agent roster. Genuinely uncovered, and six files nowhere near any threshold. Adding a class to buy zero findings buys only maintenance.

Where coverage could not be established

Stated because a survey that reports only what it found reads as complete when it isn't:

  • Whether any enabled plugin is stale — the cache lives outside the repo, and the no-outside-touch mandate stopped the check. Nothing in this repo could answer it either.
  • The content of 151 of 154 vendored instruction files; three were sampled.
  • Which guardrails are missing from the seven other worktrees.
  • An older 0/684 dark-rule measurement was not reconciled with a fresh one over a different window. Treat the old figure as inherited, not re-derived.
