## R1 / R3 — the layering

**structlog as the event layer; stdlib as the sink layer.** Verified on all three
legs in `2026-08-09-d20-structlog-stdlib-architecture.md`:
`wrap_logger` (`structlog/_config.py:155`), `ProcessorFormatter`
(`structlog/stdlib.py:1012`, **degree 37**, `JSONRenderer` community), and a
measured thread offload.

The structural evidence for the split: `logbook` ships `queues.py` with **14
transport classes**; `structlog` has **no equivalent module at all**. So
*"structlog vs loguru is not the axis"* is confirmed by shape, not asserted.

**R3's dedicated sink is a `Formatter` subclass in `kb_setup`.** Under §2.5's
ruling the stdout sink renders **product** — `kb-check`'s table, `kb-gates`'
report — so whoever owns the sink owns the shape of every report this repo
prints. Stdlib puts that in a reviewed module here; loguru and logbook put it
inside a third-party library.

**The dissent, recorded because it is real:** logbook provides
`MultiProcessingHandler`/`Subscriber`, and under `-n auto` every pytest worker is
a separate process (R12). stdlib can do it as an assembly. That row is logbook's
strongest argument and it has **not** been probed against xdist's actual worker
model.

## R2 — answered by §2.5, not by this research

**One structured event stream with a human-rendering stdout sink** (Ray,
2026-08-09). The larger of the two options, chosen over *reports stay reports,
only diagnostics get logged*. §2.5 carries the reasoning and, importantly, what
it does **not** decide.

Scope: **414** `print`/`sys.stdout`/`sys.stderr` sites across **38 of 62**
modules (§2.2).

## R4 — the mechanism, and why it is LAST

`pyproject.toml` already runs `select = ["ALL"]` and explicitly disables `T201`
with the comment *"print IS the user interface"*. Deleting that entry bans
`print` repo-wide in one line.

**Better: ruff's `TID251` banned-api table** (§2.6j, from the dotfiles session) —
also already enabled by `select = ["ALL"]` and currently banning nothing. It can
name `os.write`/`os.fdopen` too, which `T201` cannot. Both are config, no new
binary, no homegrown AST — which is what `use-tool-builtins.md` requires.

**It lands last.** Applied before a logging layer exists, it turns 414 call sites
into an unfixable-in-place lint failure.

Note §2.5's ruling **removes the need for a report-layer exemption**: with one
event stream there is no "product writes to stdout directly" category to exempt.
The sink module itself still needs one (`per-file-ignores`), which the dotfiles
session verified working.

## R5 — OPEN, and not researched

**Nothing in this round addressed R5.** *"Treat `kb_setup` as an SDK, with proper
error codes via enums (not bare ints, not ad-hoc rcs)."*

Stated plainly rather than given a plausible-sounding answer, because
`probes-need-a-control-arm.md` rule 6 is exactly about the alternative. What is
known:

- The repo currently signals through **process exit codes and printed reports**,
  which is what R5 objects to. `kb-check` and `kb-gates` return real `rc`s;
  `kb-currency` deliberately always exits 0.
- No enum-based error surface exists, and no candidate for one was screened.
- It interacts with R6: if models are generated, the error enum is a natural
  thing to generate too — but nothing here establishes that
  `datamodel-code-generator` is the right tool for enums as opposed to models.

**This is the first thing a following round should pick up**, and it needs its
own screening pass, not an inference from R1–R4.

## R6 — `datamodel-code-generator`, with a live defect

**Adoption, not restoration:** `git log -S datamodel --all` → **0** hits across
all history against **361** for `graphify` with the identical probe (§2.3).

**The live defect, reproduced end to end** against the pinned source
(`0.72.3.dev2+g56dff6a10`): `--extra-fields forbid` is **silently dropped** for
`msgspec.Struct` while working for pydantic v2. Cause is a missing default-path
reader — `extra_fields` goes to `extra_template_data`, which
`pydantic_v2/_config.py:42` reads and msgspec does not.

**Workaround, verified:** `--use-generic-base-class` emits
`Struct(_Struct, forbid_unknown_fields=True)`. Three caveats recorded before
adoption (public surface, module-global setting, `SUPPORTS_GENERIC_BASE_CLASS`
only).

**`--preset` is not the reproducibility pin it advertises** — it renames fields
to snake_case and changes the generated public API. The pin you actually want is
**`--disable-timestamp`**, which the preset bundles and which exists standalone.

## R7 — formats, and the offload

**The offload is stdlib.** `QueueListener` *is* the logging thread — measured
(handler on tid `6112407552` vs main `8526766464`) with a control arm. This is
not a library feature to shop for.

**The format decision is not settled, and the cost is measured.** `msgspec` is
C-backed and mature, but has **no `pathlib.Path` support in either direction**,
and this codebase is `Path`-saturated:

| | count |
|---|---|
| modules importing `pathlib` | **54 of 62** (87%) |
| `Path`-typed annotations | **523** |
| control — `complex` | 0 |
| control — `str` | 813 |

`Path` is **64% as common as `str`** here. The hooks are per-`Encoder`/`Decoder`
**instance**, so the cost is one shared encoder plus a decoder factory — *not*
threading through 523 sites — but `msgspec.json.encode()` silently ignores them,
which is a discipline `TID251` should enforce alongside R4.

## R8 — RULED: yes for serialisation, no for the framework

Satisfiable natively on the **serialisation** side (`msgspec` is C-backed,
`orjson` Rust-backed, both mature). **Not** satisfiable on the
**logging-framework** side: the mature C++ option `picologging` is dead by all
three instruments, and the live Rust options are `logly` (PyPI **0.2.2**, ★379)
and `logxide` (★35).

Reached independently by two routes — this repo's GitHub-commit screening and the
dotfiles session's PyPI/throughput argument (§2.6i, §2.6j).

## R12 — it constrains R1/R3 rather than following them

Under `-n auto` every worker is a separate process writing to one stdout, so
today's 414 `print` sites interleave and R9's question becomes unanswerable —
there is no single ordered stream to review. An event carries a worker field; a
`print` cannot.

**And it changes what a test may assert.** A wall-clock assertion measures the
scheduler under parallelism and reports it as the property it names. That is not
theory: it cost this round a gate failure at **73.9 ms** against a 50 ms bound,
and investigating it found **two live quadratic regexes** (§2.6g).

Sources: `pytest`, `pytest-xdist` (process axis), `pytest-run-parallel`
(thread axis, free-threaded Python — a shared process, so handler thread-safety
is live rather than sidestepped).
