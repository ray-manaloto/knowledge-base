## F1 — `_is_exempt`'s docstring still carries the exact claim round 1 struck out

**Hard violation** — `repo-smells.md`, "A doc and the code it describes
disagreeing"; `tool-currency-and-native-first.md` rule 5 ("Sync the describing
docs/skills in the SAME change").

`python/src/kb_setup/review.py:624-628`:

```python
def _is_exempt(path: str) -> bool:
    """Return whether ``path`` is one a review lane cannot cover (:data:`EXEMPT_PATHS`)."""
```

Round 1 finding #3 removed precisely this framing from `EXEMPT_PATHS`, and the
replacement comment 500 lines up now states it is **false**, in bold, as the
central lesson of the round (`review.py:100-104`):

> **That timing is the whole justification, and it is the only one.** The first
> draft of this comment also claimed these were "paths a review lane cannot
> meaningfully review" — which the review of this very commit falsified: three
> lanes found three live credentials pasted into one of these files by
> `kb-remember`. A lane reads them fine. What it cannot do is read them before
> they exist.

So the fix corrected the claim at the constant and left it verbatim at the
helper that implements the constant. A reader landing on `_is_exempt` — the
function a future widener will edit — gets the retracted rationale, which is the
one that invites widening the set. The whole point of round 1's rewrite was that
"a lane cannot read these" is the reasoning that produces an unsafe exemption.

Fix: `"""Return whether ``path`` is one the round's own closing tasks write
after the review (:data:`EXEMPT_PATHS`)."""`

**This is what the round-1 fix introduced**, not a re-report of the original.

## F4 — the gitleaks-scope probe uses a *different regex engine* than the thing it pins

**Judgement call**, but it lands squarely on `probes-need-a-control-arm.md`
(a probe that cannot produce one of the answers) and it is the *only* gate on a
config the diff itself calls a **precondition** for `EXEMPT_PATHS`.

`tests/test_gitleaks_scope.py`:

```python
def _allowlisted(path: str) -> bool:
    return any(re.search(pattern, path) for pattern in _allowlist_paths())
```

`.gitleaks.toml`'s own new comment establishes the divergence it is about to be
tested through:

> ENUMERATED rather than negated: gitleaks' regex engine is Go RE2, which has
> no lookahead — `^graphify-out/(?!memory/)` does not compile, measured
> (`invalid perl operator: (?!`).

Python's `re` **does** compile `(?!…)`. So the exact repair someone would reach
for next time — re-simplifying seven enumerated patterns back into one negated
one — passes this test suite and breaks gitleaks at run time. The test can
produce "allowlisted / not allowlisted" but cannot produce "gitleaks rejects
this config", which is a failure mode the config comment documents as having
already happened once.

The docstring's justification is sound as far as it goes ("a test that shells
out to a pinned binary answers a slower question less directly") — but the
control arm it cites is a *comment* recording a manual run, not a re-runnable
one. A cheap closing move that keeps the fast test: assert each pattern is
RE2-compatible (no `(?!`, `(?=`, `(?<`, backreference), or add one
`gitleaks detect --config` smoke over a synthetic fixture.

Two lesser notes in the same file, both fine as-is but worth naming:

- `re.search` (not `fullmatch`) is the right choice — gitleaks' semantics are
  search — but it is unstated, so a future author may "tighten" it to `match`.
- `_MUST_SKIP` covers `cache/`, `wiki/`, the dated dirs and top-level files, but
  no arm covers `converted/`, `obsidian/`, `transcripts/` or `reflections/`,
  which are in the pattern and untested. Low value; the shape is proven.

## F5 — `_covering_receipt` discards a boolean its callee computed, and the caller re-derives it

**Judgement call** — Fowler, *Primitive Obsession* / *Message Chains*-adjacent:
state is smuggled through a `(str, str)` pair and reconstructed by inference.

`review.py:690-731` returns `(sha_to_validate, note)`. The accepted/refused
distinction is then reconstructed at the call site (`review.py:821`):

```python
covering, note = _covering_receipt(repo_root, sha, require_base)
refused = bool(note) and covering == sha
```

`_exempt_delta_note` already returns an explicit `tuple[bool, str]` — the
information exists and is deliberately dropped one frame up, then guessed back
from an identity comparison. Two live consequences:

1. `refused` is **true for a case that is not a refusal**: when
   `_reviewed_ancestors` finds nothing, `_covering_receipt` returns
   `(sha, "and no commit below it on this branch has one either")`. That is "no
   candidate existed", not "a candidate was refused". It currently renders
   correctly by luck — that string was written to read well after "no review
   receipt for X," — but the variable name asserts something the value does not
   mean.
2. `suffix = f" — {note}" if note and not refused else ""` (`review.py:834`)
   encodes the same three-way state a third time, in a third shape.

The module's own docstring standard is that "could not check" / "refused" /
"accepted" stay distinct (`repo-smells.md`: "Collapsing 'could not check' into
'clean'"). Returning `(covering_sha, outcome_enum, note)` — or reusing the
`(bool, str)` shape `_exempt_delta_note` already has — would make the three
states nameable instead of inferable.

## F6 — the #66 rationale is now restated in seven places

**Judgement call** — Fowler, *Shotgun Surgery* (one logical change forces
scattered edits) applied to prose rather than code.

The same narrative ("P7 writes files that cannot exist until after the review,
so an ancestor's receipt covers HEAD when the delta is exempt; three rounds
running left them uncommitted, one `git clean -xdf` from gone") appears at:

1. `review.py:16-20` — module docstring
2. `review.py:92-124` — the `EXEMPT_PATHS` comment block
3. `review.py:691-716` — `_covering_receipt` docstring
4. `review.py:805-809` — `receipt_state` docstring
5. `.claude/skills/kb-review/SKILL.md:231-244`
6. `.claude/skills/goal-engineering/SKILL.md:147-153`
7. `tests/test_gitleaks_scope.py:11-15` module docstring (+ several test
   docstrings)

`.gitleaks.toml`'s comment makes eight for the coupled half. Several are near
word-for-word ("one `git clean -xdf` from gone" appears in 3; "three rounds
running left them uncommitted" in 4).

This repo *does* endorse dense explanatory prose — `review.py` already carried
essay-length docstrings before this diff, and `CLAUDE.md`/the rules are written
the same way, so the style is not the finding. The finding is the **fan-out**:
narrowing or widening `EXEMPT_PATHS` now requires editing seven prose sites to
stay honest, and F1 above is the first one that already failed to keep up, in
the very commit that created the fan-out.

Suggested consolidation: one canonical account at `EXEMPT_PATHS`; the other six
become one-line pointers to it (`see EXEMPT_PATHS`). The two SKILL.md entries
legitimately need a user-facing summary, but they need the *workflow*
(review → receipt → closing tasks → commit → ship), not the incident history.
