## (b) Behaviour not asked for (scope creep)

### B1 — `65caf23` (gitleaks scope fix + `tests/test_gitleaks_scope.py`): **belongs on this branch**

Neither spec source asks for it. The commit body's argument is:

> the exemption removes the only lane read these paths get, so SCANNER coverage
> of them is a precondition

**I judge the argument sound, and would keep it here.** Three reasons:

1. It is a genuine precondition in the logical sense, not a rhetorical one.
   `EXEMPT_PATHS` makes `graphify-out/memory/**` a path that **no lane and no
   scanner** reads. Landing the exemption first would knowingly create a
   commit-shaped hole into a public repo.
2. It is not hypothetical. `eb91aaf` is the commit that folds in a memory file
   which — per both commit bodies — contained three live credentials pasted
   verbatim by `kb-remember`. **Verified the remediation:**
   `graphify-out/memory/query_20260728_072907_….md` now names kinds only
   (*"an Exa API key and two GitHub PATs"*) and no credential-shaped string
   appears in any of the three folded files. Ordering the scanner fix *before*
   the fold is the only safe order.
3. The coupling is enforced, not asserted:
   `tests/test_gitleaks_scope.py:94-102` derives its must-scan set from
   `review.EXEMPT_PATHS`, so widening the exemption cannot silently outrun the
   scanner. That is the right shape for "precondition".

**Recommendation: keep, do not split.** Splitting would either ship the
exemption with a known blind spot, or ship the fold with credentials under a
blind scanner.

## (c) Implemented but the implementation looks wrong

### C1 (low) — `docs/goals/README.md` is exempted as a whole file, where the spec's need is one table cell

Spec: *"`docs/goals/README.md`'s change is one table cell: the `Legible` pair's
status, `not started` → `achieved`."*

`EXEMPT_PATHS = ("graphify-out/memory/", "docs/goals/README.md")` with
`_is_exempt` doing an exact-path match, so **any** change to that file — a
rewritten rationale section, a deleted table, the "Why the goal file is capped at
4,000 characters" prose — ships on an ancestor's receipt with no lane read.

This is what issue #66's comment literally suggested, so it is *spec-compliant*.
But it is the one place where the implementation is broader than the
demonstrated need, and it is the exempt entry a human is most likely to hand-edit
for reasons unrelated to P7. `docs/goals/README.md` is 100% prose, so the blast
radius is bounded, and `test_gitleaks_scope.py` keeps the scanner on it.

**Suggested, not blocking**: if a future round wants to narrow this, the honest
narrowing is content-shaped (only the Status column changed), which the code's
own comment rules out on purpose (*"a pattern language here would be a second
thing to get wrong on the gate's permissive side"*). Recording the trade-off is
probably enough. No action this round.

### C2 (low) — an exempt-path **deletion** is accepted the same as an addition

`_delta_paths` uses `git diff --name-only`, which reports deletions. A commit
that deletes `graphify-out/memory/*.md` is exempt-only and therefore ships on an
ancestor's receipt unreviewed. The spec's motivating case is only ever
*additions* (`kb-remember` writes files) plus one *edit*
(`kb-goal-outcome`).

Genuinely low risk — work-memory is recoverable from git history and the whole
point of #66 is that these files were being *lost*, not falsified. But the
docstrings claim the check proves *"the shipped tree equals a reviewed tree
except in exempt paths"*, which is true and is exactly why a deletion passes.
Worth one sentence in `EXEMPT_PATHS`' comment so it is a decision rather than a
consequence.

### C3 — I could not fault the core mechanism

Checked against the spec's *"change the check, never remove it"*:

- The gate is not weakened, only re-pointed. `_base_coverage_gap` and
  `_all_reasons` both still run, against `covering`
  (`review.py:822`, `:826`) — pinned by
  `test_the_ancestors_own_receipt_still_has_to_pass` (blocking finding on the
  ancestor still refuses).
- The ancestry walk is bounded to `main..sha` — pinned by
  `test_the_walk_does_not_reach_a_receipt_on_main`.
- `--no-renames` — pinned by `test_a_rename_out_of_a_reviewed_path_refuses`.
- Fail-closed on an unreadable diff (`_git_result`'s separate ok flag) — pinned
  by `test_an_unreadable_delta_fails_closed`, which carries its own control arm.
- Prefix-vs-exact matching, including the `graphify-out/memory-of-a-thing.md`
  near-miss — pinned by `test_exempt_paths_match_prefixes_and_exact_files`.
- The `(+N more)` bound is applied on the **accepted** branch too, not just the
  refusal — pinned by `test_an_accepted_fallback_is_summarised_too`.
- Option (2) was taken, not (1) — confirmed: the paths are *not* excused inside
  a delta containing code (`test_one_reviewed_path_in_the_delta_refuses`).

This is the narrower option the spec asked for, implemented as asked.
