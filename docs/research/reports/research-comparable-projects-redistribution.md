# Prior Art: Redistribution & Attribution in Derived-Content Aggregation Projects

> Persisted **verbatim at receipt** per `.claude/rules/agent-report-persistence.md`.
> Sub-agent delegation of question (d) from `research-corpus-licensing.md`.
> Received 2026-08-02. Not edited, trimmed, or normalised.

### 1. tldr-pages (`github.com/tldr-pages/tldr`)

- **Licence of the artifact:** Dual — page **content is CC-BY-4.0**, the client/tooling code under `scripts/` is **MIT**. Verbatim from `LICENSE.md`: *"This work is licensed under the Creative Commons Attribution 4.0 International License."*
- **Redistributed vs linked:** Fully redistributed — the pages themselves are the product, hand-authored (not scraped verbatim).
- **Attribution mechanism:** The CC-BY licence itself, applied to the whole corpus as one grant. No per-page/per-contributor attribution manifest. A signed CLA (via cla-assistant.io) is required before any contribution merges, which is what lets the project hold a clean, uniform CC-BY grant regardless of each contributor's original knowledge source.
- **Man-page derivation policy:** No explicit "don't copy from man pages" clause exists. The project instead scopes itself deliberately *smaller* than a man page ("that's what `man` is for" — CONTRIBUTING.md) rather than banning derivation outright. The one hard originality gate that does exist targets **generative AI output**, not man-page-derived content.
- **Opt-out/takedown:** Not found; not really applicable since content is authored, not scraped from a single external rights-holder.
- **Lesson for us:** A CLA + one uniform licence works when contributors *write* the content. It doesn't transfer to our case, where content is *extracted* from ~33 external repos we don't own — our provenance mechanism (source URL + pinned SHA) is doing tldr's CLA's job.

### 2. DevDocs (`github.com/freeCodeCamp/devdocs`) — closest analogue, most load-bearing finding

- **Aggregator licence:** MPL-2.0 for the scraper/app code (`LICENSE`, `COPYRIGHT`). This covers the *tool*, not the redistributed third-party doc content — each source's licence governs its own content.
- **What's redistributed vs linked — BOTH, on two separate tracks:**
  - **Recipe (in git, MPL-2.0):** every source is a small Ruby scraper class (`lib/docs/scrapers/*.rb`), fully public and re-runnable (`thor docs:generate <doc> --force`).
  - **Corpus (NOT in git — `.gitignore` excludes `public/docs/**/*`):** built and pushed to DevDocs' own infrastructure — `s3://devdocs-documents/` (read live by the running web app at `documents.devdocs.io`) and `s3://devdocs-downloads/` (pre-built `.tar.gz` bundles fetched by `thor docs:download`). The live app and its offline service-worker also fetch `index.json`/`db.json` straight from that CDN at runtime.
  - Net: **ship the recipe in git + ship the corpus separately off-repo, generated by the project's own infra** — not an either/or.
- **Attribution mechanism — code-enforced, not documentation-only:** every scraper *must* set `options[:attribution]`, wired into the default filter pipeline (`AttributionFilter`) so licence text is appended to **every scraped page's footer**, and the same field feeds a live-rendered public table at `devdocs.io/about` ("Documentation | Copyright/License | Source code"). Concrete examples pulled from source: MDN → CC-BY-SA text; Python → PSF License text; Bootstrap → split MIT-code/CC-BY-docs text. `docs/adding-docs.md` makes setting this field a mandatory step of the contribution checklist, and the update checklist requires re-checking it stays correct over time.
- **Opt-out/takedown:** Control-armed search (CONTRIBUTING.md, maintainers.md, GitHub issue search for takedown/DMCA/"remove documentation") found **no documented takedown process** — the same search method reliably surfaces real licensing threads elsewhere in the repo (see next bullet), so the absence is real, not a broken probe. What exists instead is a strict **pre-inclusion gate**.
- **Inclusion gate with real rejection precedent:** `CONTRIBUTING.md`: *"the documentation's license must permit alteration, redistribution and commercial use, and the documented software must be released under an open source license."* Maintainer-confirmed rejections on GitHub issues: MongoDB (#397, CC-BY-NC-SA — NC clause fails the "commercial use" bar), Apple/Swift docs (#315, proprietary despite open source code), Microsoft/.NET docs (#158/#467, rejected then re-admitted once relicensed to CC-BY-SA), plus a standing named blocklist (MySQL, ElasticSearch, MongoDB, Apple, Microsoft, Adobe).
- **Lesson for us:** DevDocs' answer is: **make the per-source licence a required, machine-enforced field that gates ingestion AND is rendered publicly**, not a side note — and separate the *recipe* (small, public, git) from the *corpus* (large, regenerated, distributed off-repo). This maps almost exactly onto our `sources/*.manifest` (recipe) vs `graphify-out/` (gitignored corpus, served via `kb-serve`) split — the missing piece is a DevDocs-style mandatory per-source licence field with a hard inclusion gate and a public rendering.

### 3. Zeal / Dash-User-Contributions (`github.com/Kapeli/Dash-User-Contributions`)

- **Per-docset licence field:** **None exists.** Live-fetched `docsets/AWS_CLI/docset.json` schema is limited to `name`/`version`/`archive`/`author`/`aliases`/`specific_versions` — no `license` key anywhere in the schema, and `README.md` gives no content-licensing guidance at all.
- **Host or link:** Hybrid, and transient by design — the README states generated docset archives are **automatically removed from the git repo once distributed to Kapeli's own CDN**: *"As soon as your docset gets distributed to my CDN, it will get removed from the repo automatically."* Confirmed empirically: an old approved docset (`Bash/`) is now an empty git folder; a newer one (`AWS_CLI/`) still shows the pre-distribution artifact. So the generation *script* stays in git permanently; the generated *corpus* is redistributed by Kapeli, from his own CDN, licence-unlabeled.
- **Attribution mechanism:** None beyond an `author` field crediting the docset's *submitter* (not the upstream doc source).
- **Opt-out/takedown:** Not documented; not applicable in the same way since Kapeli alone controls the redistribution surface.
- **Lesson for us:** A no-licence-field pattern only works when one person/entity controls both generation and the sole redistribution channel and nothing downstream re-redistributes it. We don't have that — `kb-serve`/a pushed graph DB is itself a redistribution surface others query — so we can't skip the field the way Dash does.

### 4. awesome-lists

- **Convention:** CC0 is the flagship's explicit, named recommendation (`sindresorhus/awesome`'s own manifesto: *"We would recommend `CC0`"*; the repo's own `license` file is CC0 1.0). `awesome-lint`'s enforcement is negative-only — it flags a forbidden inline "license" heading in the README (push licence info to a separate `LICENSE` file) rather than whitelisting specific identifiers.
- **CC-BY-NC-ND prevalence / derivative-work tension:** **No specific written discussion found**, despite four differently-worded searches (generic license-compatibility explainers and one unrelated issue, `sindresorhus/awesome#1598`, about the CC0 GitHub-picker UX, were the only hits). Control-armed conclusion: this appears to be a genuine absence in easily-discoverable public writing, not a broken search — plausibly *because* the CC0-only convention structurally prevents the NC-ND collision from ever needing to be litigated in the first place; a list that carries NC-ND simply never gets included upstream.
- **Lesson for us:** The preventive posture — refuse a source whose licence would restrict re-derivation, rather than hoping to litigate compatibility later — is the transferable idea, independent of the missing case study.

### 5. HuggingFace `datasets`

- **`license:` field convention:** A single YAML enum value (~85 identifiers: `apache-2.0`, `mit`, `cc-by-4.0`, `odc-by`, plus catch-alls `unknown`/`other`). For `other`, the spec requires an in-repo `LICENSE` file plus a `license_name` field. **There is no per-source/multi-value license schema** — the metadata model simply doesn't support it.
- **How real multi-source datasets cope:** Prose, not YAML. RedPajama-Data-1T's card has no unified `license:` value; the body states *"Please refer to the licenses of the data subsets you use"* with a per-source table (Common Crawl → CC ToU; GitHub → "limited to MIT, BSD, or Apache licenses only"; C4 → AllenAI's licence; etc.). The dataset-card template's guidance is explicitly *"[More Information Needed]"*-tolerant, best-effort prose.
- **Takedowns/gating — two separate, non-licensing mechanisms:** "Gated" datasets are an opt-in *consent-collection* wall the author configures (access requests, EU geoblock flag) — not a copyright review gate. Real takedowns run through a **reactive DMCA process** (`dmca@huggingface.co`, disable-on-valid-claim, uploader counter-notice, 14-business-day restoration window) — i.e. HF verifies nothing proactively at upload time.
- **Lesson for us:** Put one representative `license:` tag (or `other`/`unknown`) at the top for discoverability, and put the real per-source breakdown in prose — there's no multi-license schema in this ecosystem to lean on, so inventing one for our manifest is genuinely novel work, not something to skip because "everyone else has one."

### 6. Common Crawl

- **Position:** Mission-based ("democratize the data"), not a stated legal theory. **Terms of Use** (`commoncrawl.org/terms-of-use`) push copyright risk entirely onto the user and original site owner: *"YOU AGREE TO RESPECT THE COPYRIGHTS AND OTHER APPLICABLE RIGHTS OF THIRD PARTIES,"* content is "AS IS," all warranties disclaimed including non-infringement, and users must **indemnify** CC for third-party IP claims, explicitly including AI-system uses.
- **Opt-out:** Prospective only — `robots.txt` `Disallow: /` for CCBot, plus a separate opt-out registry. **No documented retroactive takedown** of already-published archives.
- **Lesson for us:** "As-is, no warranty, respect third-party rights, plus a forward-only opt-out" is the field's accepted floor for a raw scraped corpus. We should at minimum match it (disclaimer + honor removal requests going forward) — our situation is arguably lower-risk since we extract semantic `{nodes,edges}`, not full-text.

### 7. The Pile (Books3 takedown)

- **Timeline** (EleutherAI's own repo is the primary source for the fact of removal; the DMCA/Rights-Alliance/lawsuit specifics rest on Wikipedia's "The Pile (dataset)" article, itself citing outlets — Wired/Verge/Ars Technica/Gizmodo/404 Media — that were unreachable to verify directly in this session, so flagged as secondary corroboration): Books3, sourced from the shadow-library site Bibliotik, shipped with The Pile from Dec 2020. In **July 2023**, Danish anti-piracy org **Rights Alliance** issued DMCA notices; Books3 came down from its main hosting points. A **2024 class-action** followed against downstream users (reported to include Meta). EleutherAI's current `README` marks the component *"Download temporarily unavailable"* with no further public statement.
- **Independent corroboration:** RedPajama's own dataset card independently flags its Gutenberg/Books3-adjacent component as **"Defunct" due to reported copyright concerns** — a second, unrelated project reaching the same conclusion.
- **Lesson for us:** The field's default response to a provenance-hostile source, once challenged, is **quiet retroactive removal, not defense**. Worth deciding now — before ingestion, not after a complaint — which of our 33 sources (all public GitHub repos with their own OSS licences, which is a materially better starting position than Bibliotik/pirated books) would need pulling under pressure, and confirming none resemble the Books3 shape.

### 8. C4 / RedPajama

- **C4** ships actual derived, filtered/deduped text under **ODC-BY 1.0**, with an explicit pass-through: *"also bound by the Common Crawl terms of use."* This is "ship the corpus" — AllenAI asserts a licence over their *curation layer* only.
- **RedPajama** is closer to "ship the recipe": the GitHub repo is the **processing pipeline** (Apache-2.0 for the code), and for content licensing it defers entirely: *"please refer to the Common Crawl Foundation Terms of Use."* The assembled HF dataset does distribute derived text, but again refuses a single licence tag in favor of a per-source table.
- **Lesson for us:** RedPajama's "defer + per-source table" is more defensible than C4's "assert one blanket licence" when you can't independently clear every source — matches what our `sources/*.manifest` provenance already does; the gap is that we don't yet *publish* the per-source table the way RedPajama's card does.

### 9. NOTICE files / attribution manifests

- **Apache-2.0 §4(d)** only obligates preserving an upstream NOTICE file's *own* contents when redistributing an Apache-licensed derivative — it's not a general mechanism you can invent for arbitrary MIT dependencies. **MIT has no NOTICE concept**; its sole condition is including that project's own licence text "in all copies or substantial portions."
- **Concrete precedent at scale — Kubernetes:** no single root NOTICE file. Instead `LICENSES/vendor/<module-domain>/<org>/<repo>/LICENSE` — every vendored dependency's actual licence text mirrored at its own path, generated via Go tooling. Verified live against the repo tree.
- **Lesson for us:** A single hand-written NOTICE doesn't scale past a handful of sources and doesn't satisfy MIT's per-project text-preservation condition anyway. Kubernetes' `LICENSES/<source>/LICENSE` mirror — generated at `kb-build` time from each `sources/*.manifest` pin, verbatim-copied from the pinned commit — is the directly transferable pattern for ~33 sources.

---

### 10. "Ship the recipe, not the corpus"

Three verified, concrete examples beyond DevDocs:

- **`NixOS/nixpkgs`** — every derivation uses `fetchurl`/`fetchFromGitHub` with a pinned URL + content hash; upstream source is fetched at *build* time, never vendored.
- **`Homebrew/homebrew-core`** — verified live (`Formula/r/ripgrep.rb`): `url` + `sha256`, fetched from upstream GitHub at the *user's* `brew install` time, never from Homebrew's own git history.
- **`rom1504/img2dataset`** — takes a user-supplied URL list and downloads/processes **on the end user's own machine**; the tool itself never redistributes the images.

All three sidestep redistribution licensing entirely by construction: ship instructions + an integrity hash, let the *user's own access* to the upstream do the fetching.

## Synthesis: the field has converged on 3–4 distinct patterns

1. **Disclaim, don't verify.** Every large scraped-corpus project (Common Crawl, HF, The Pile, C4/RedPajama) pushes copyright responsibility downstream to "the original site" or "the licences of the subsets you use," rather than asserting cleared rights. Enforcement is reactive (DMCA-on-complaint), not proactive per-source review — **except DevDocs**, which is the one project in this set that *does* review and gate at ingestion time.
2. **Recipe vs corpus is a real, load-bearing distinction**, and the strongest projects ship *both*, on separate tracks: the regenerable extraction logic stays small, public, permissively licensed (MPL-2.0/Apache-2.0 code); the generated artifact is either not redistributed at all (nixpkgs/Homebrew/img2dataset) or redistributed from separate, purpose-built infrastructure outside the source repo (DevDocs' S3/CDN, Dash's CDN) — never committed to git wholesale.
3. **Per-source attribution beats one aggregate blanket licence, and it should be machine-readable, not prose-only, once you have "many sources."** HF and RedPajama fall back to prose tables because their platform's schema has no per-source field; DevDocs and Kubernetes prove a code-enforced, per-item field (`options[:attribution]` / `LICENSES/vendor/<path>/LICENSE`) that gates inclusion AND renders publicly is achievable and is the stronger design once you're past a handful of sources.
4. **A hard inclusion gate with named rejections beats an after-the-fact takedown policy.** DevDocs is the only project in this set with a documented, enforced pre-inclusion licence bar ("must permit alteration, redistribution and commercial use") and a public paper trail of specific rejections (MongoDB, Apple, Microsoft, Adobe) — everyone else (Common Crawl, HF, The Pile) instead relies on opt-out-going-forward or reactive DMCA, and The Pile's Books3 history shows what the reactive-only path costs when it goes wrong.

**Direct implication for this repo:** we already have the recipe/corpus split right (`sources/*.manifest` + gitignored `graphify-out/`, served via `kb-serve`). What's genuinely missing, per this research, is (a) a DevDocs-style mandatory per-source licence field in the manifest that gates ingestion and is queryable/renderable, and (b) a Kubernetes-style `LICENSES/<source>/LICENSE` mirror generated at build time — both are concrete, cheap, and precedented, unlike inventing a machine-readable multi-license schema from scratch (nobody in this survey has one).
