## MISSING premises

**1. `tests/test_graphify_semantic_corpus.py:2562` hard-asserts `config["max_total_cost_usd"] == 100.0`** on a **freshly built** synthetic plan (`plan_source` at `:2550`). It is neither the authority test nor an on-disk-plan decoder, so §4's excused list does not cover it — it **will go red on the 140.0 change and must be updated in this lane**. The neighbouring `!= config["max_cost_usd"]` assertion survives.

**2. §4's CLI FAIL-arm demo cannot produce the named reason.** `_manifest_reasons` (`:1379-1404`) re-hashes every member against `manifest.json` (`:1402-1403`) and `verify_plan` **returns early** at `:1739-1745` on any such reason. Hand-editing the scratch plan's `execution-config.json` yields exactly `("member-digest-mismatch:execution-config.json",)` with `structural_complete=False`; `_cross_reasons` never runs, so `plan-graphify-runtime-mismatch` can never appear. The reason is not "plus" — it is *exclusive and early-returning*. Correct demo: edit the config **and** rewrite that member's `sha256` + `size` in `manifest.json` (`manifest.json` is not in `_PLAN_MEMBERS` and is not self-checked; authority is unset on a scratch plan, so the authority branch is reached only after cross reasons).

**3. `runtime_identity` refuses rather than reports, and it raises `SystemExit`.** It calls `graphify_env.assert_pinned_graphify(repo_root)` (`graphify_env.py:152-183`), which raises **`SystemExit`** when pin ≠ running binary — the live stale-PATH scenario this repo already records in memory. It also raises `ValueError` on an unreadable `uv.lock`, a `graphifyy` package count ≠ 1, an executable outside the repo, or release/CLI/SDK disagreement. Two consequences the spec does not state: (a) putting this on the verify path makes `verify_plan` — today a total function — able to raise, so `corpus_main`'s `verify` route can exit without printing a verdict and the `run` route can bypass `_abort` entirely; (b) the mismatch the new reason can express is *plan ≠ (pin == live)*, **never** *plan ≠ live*, because the measurement refuses to describe a runtime that disagrees with the pin. Decide explicitly: catch and convert to a reason (e.g. `plan-graphify-runtime-unmeasurable`), or let it propagate.

**4. `graphify_semantic_corpus_prototype.py` is a third caller of both surfaces and is absent from §2.** It calls `graphify_semantic_corpus.verify_plan(plan, source_root)` **positionally** at `:336` and `:371`, strict-decodes `CorpusExecutionConfig` at `:163`, `:177-178`, `:258-259`, `:434`, and passes `graphify_version=config.graphify_version` into `graphify_semantic_slice.preflight` at `:375`.
