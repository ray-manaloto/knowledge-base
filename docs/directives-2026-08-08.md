## 2. THE ARCHITECTURAL PROGRAM — recorded, NOT built

Ray, 2026-08-08. **In a fenced block deliberately: this is the record that must
not drift, and a fence is the only markdown construct `rumdl` will not reflow.**
As a blockquote the formatter had already inserted a `>` spacer and wrapped the
bare URL in `<>` — cosmetic, and still an edit to words filed as verbatim.
Typos (`stderror`, `loggign`, `the the`) are Ray's and are kept.

```text
and all the python code should be using a modern asynchronous library that supports structured logging of different formats via sinks
- there should be no direct stdout/stderror calls and only via the logging library
  - if it output needs to be in stdout/stderr it should be its own dedicated sink
  - we should enforce this via hk/ruff/graphify's tree-sitter/ty lsp to block stdout/stderror from ever writing out

the python library should be treated as an sdk with proper error codes via enums

i think we've also drifted away from only having models and code generated from https://github.com/koxudaxi/datamodel-code-generator
with modern efficient message formats that the loggign library can offload to the the logging thread

the logging library can be a rust/c++ library if it is more efficient if it provides python bindings
```

### 2.1 Requirements, itemised

- **R1** — a modern **asynchronous** logging library, **structured**, emitting
  **multiple formats** via **sinks**.
- **R2** — **no direct `stdout`/`stderr` calls** anywhere; all output goes
  through the logging library.
- **R3** — output that genuinely must reach stdout/stderr gets its **own
  dedicated sink**.
- **R4** — **machine-enforce** R2 via hk / ruff / graphify's tree-sitter / the
  ty LSP, so a direct write can never land.
- **R5** — treat `kb_setup` as an **SDK**, with **proper error codes via enums**
  (not bare ints, not ad-hoc rcs).
- **R6** — models and code **generated from
  [`koxudaxi/datamodel-code-generator`](https://github.com/koxudaxi/datamodel-code-generator)**,
  not hand-written.
- **R7** — **modern efficient message formats**, so the logging library can
  **offload serialisation to the logging thread**.
- **R8** — the logging library **may be Rust/C++** if that is more efficient,
  provided it ships Python bindings.
- **R9** — **the verification process must review the logs for warnings/errors
  that might be silently skipped**, which structured logging makes findable
  fast. Ray, verbatim:

  ```text
  and our verification process needs to review the logs for warnings/errors that might be silently skipped
  - can be found faster via structured logging
  ```

  R9 is not a nice-to-have inferred from the others — it names the failure this
  repo keeps paying for, and it was demonstrated **twice in the session that
  produced this document**:

  | live instance | what was buried |
  |---|---|
  | `mise run fmt` exited **1** with `✗ ruff – ERROR` and no detail, every other step `✔` | three real lint errors, findable only by running `uv run ruff check` directly — the task's own output could not say what failed |
  | `mise run kb-watch` exited **1** | the cause was a `WARNING … net -90 … Refusing to overwrite` at line 22 of 71, followed by `[merge] ERROR: to_json refused (shrink guard #479)`, under a traceback naming a *different* chunk than the one that actually failed |

  Both are the same shape: a non-zero rc whose REASON is somewhere in a stream
  nobody greps, attributed to the wrong place. `zero-skip-policy.md` already
  forbids dismissing a warning; R9 is the mechanism that would make the warning
  **findable** rather than relying on someone scrolling. Note it composes with
  R2/R3: once every subprocess's output is an event with a level and a source,
  "did this run emit anything at WARNING or above?" becomes a query rather than
  a read.

### 2.4 What is already built and merely switched off

**R4's basic form is one line.** `pyproject.toml` sets `select = ["ALL"]`, which
includes ruff's `T201` (flake8-print) — and this repo explicitly disables it:


Deleting that entry bans `print` repo-wide with no custom checker, no
tree-sitter and no ty-LSP work. Ruff also ships the `LOG` and `G` rule families

### 2.5 The open design question, stated so it is not decided by accident

That suppression comment names the real tension: **most of the 414 sites are the
product, not diagnostics.** `kb-check`'s summary table, `kb-gates`' report,
`kb-session-reflect`'s report and `kb-currency`'s run log are read by humans and
in places parsed by machines. R3 appears to anticipate exactly this — the
question put to Ray, and **not yet answered**, is whether the intent is *one
structured event stream with a human-rendering stdout sink* rather than
*reports become log lines*.

### 2.6 Explicitly NOT decided

not one existing package; it is a combination of an event model, a

(`probes-need-a-control-arm.md` rule 6). This needs a research pass against
current sources, per `research-doc-sources.md` and
`tool-currency-and-native-first.md`.

## 3. Findings that outlive this round

### 3.1 The corpus has never had a deep extraction

Measured over all 25 committed chunks: **0 `AMBIGUOUS` edges** of 6,441, and
**9.3% `INFERRED`**. Deep mode's own spec says "mark uncertain ones AMBIGUOUS
instead of omitting", so zero is the signature of its absence.
`.claude/workflows/kb-extract.js` never mentions `DEEP_MODE`.

Two things that looked like gaps and are **not**, checked rather than assumed:

- "4,798 nodes carry no summary" — `summary`/`description` are **not in the
  extraction schema at all**. The specified field is `rationale`, present on 73%.
- "17 of 25 chunks have 0 hyperedges" — within spec: "use sparingly", max 3 per
  subagent chunk.

Live: **relation-vocabulary drift** — ~280 distinct relations against the 8 in
the schema line, and the top relation `part_of` (1,762 = 27% of edges) is not
among them. Only `file_type` carries a MUST, so it is not spec-forbidden, but no
query can rely on a relation name.

### 3.2 `kb-watch` was broken; the graph could not be recomposed

`build()` and `refresh_self()` each had their own replay loop. `build()`'s
applied `chunks.replay_order` and threaded `--prior-<field>`; the recomposition
loop did **neither** — it replayed `manifest.chunks` in stored (alphabetical)
order and checked no arithmetic. Same corpus, two graphs, chosen by the alphabet:
the exact defect `chunks.replay_order` exists to remove, fixed on one path and
left live on its sibling.

Cost: `claude-code-docs-mirror` (captured 07-30, 26 nodes) replayed **after**
`claude-code-docs-2026-08-05-refresh` (08-05, 116 nodes) and superseded it —
`hooks.md` 69 → 5, `skills.md` 47 → 15, net **−90** — and only graphify's #479
shrink guard refusing the write kept the regression off disk.

Fixed with one shared `_replay_pairs` both callers route through, plus a named
`chunks.replay_key` so the sort key cannot be re-derived in two places. Verified
end to end: `kb-watch` rc=0, **359,069 nodes / 881,532 edges / 122 hyperedges,
0 lost, 0 dangling**.

**Why it mattered beyond the corpus:** the self-graph was stale by exactly the
newest modules (`session_reflect.py`, `graph_first.py` and both tests were
absent), so graph-first orientation on them could not work — the mandated query
returned foreign AST noise, source got read anyway, and the guard scored the one
query as compliance. Both modules now resolve via `graphify explain`.

### 3.3 22 of 25 chunks' derived replay root does not exist

`_replay_targets` derives `sources/<stem minus -docs>`; the override map
`chunk_roots` that exists for this case is **empty `{}`**. Survivable — the root
is only used to relativise — and **not** the cause of §3.2, which was ordering.
Recorded because it is still latent.

### 3.4 `${PIPESTATUS[0]}` is inert in this repo's shell

Armed both directions, zsh 5.9 (`BASH_VERSION=none`):

| construct | failing gate | passing gate | discriminates? |
|---|---|---|---|
| `${PIPESTATUS[0]}` | `''` | `''` | **no** |
| `${pipestatus[1]}` | `1` | `0` | yes |

`PIPESTATUS` is a **bash** array; zsh spells it `pipestatus`, indexed from 1.
Worse than useless: `piped-rc`'s exemption searched the whole command for the
bash spelling, so writing it bought a **full exemption while capturing nothing**
— the fourth too-wide version of that one exemption. Now exempts
`${pipestatus[1]}` only.

### 3.5 The `piped-rc` investigation: the detector was innocent

Over the 2026-08-08 transcript, **17 of 17 flagged commands were real**. Zero
false positives — **none** was the `> log; echo "rc=$?"` form the prior handoff
guessed at. Zero false negatives against a looser arm. Control-armed four ways:
violation fires, documented remedy silent, `${PIPESTATUS[0]}` silent,
`kb-query | head` silent.

What was actually wrong was the **report** — and, underneath it, the mandate:

1. `scan()` returned on the first match, so `xN` counted **commands** while
   reading as violations (17 reported, **35** real).
2. The violations section printed **no excerpt at all**, while every other
   section did — which is why the count was never checked and was speculated
   about instead.
3. Ray's question exposed the cause: the rule's remedy was
   `<cmd> > /tmp/out.log 2>&1; echo "rc=$?"` — **shell logic recommended by the
   repo whose first invariant forbids it** — and all 35 violations were
   hand-rolled gate invocations that a mise task should have owned. `check` is
   whole-repo and `kb-gates` runs the ship gates; **nothing answered "are these
   two files clean?"**, and that vacuum was filled 35 times with a pipe.

Remedy now points at **`mise run kb-check -- <paths>`**, new this round.
