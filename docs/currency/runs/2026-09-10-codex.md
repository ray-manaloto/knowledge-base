## Annotation — a start-blocking change the release notes never mentioned

Added while advancing `sources/codex-docs.manifest` (work-order step 3), which is
a different pin from the one this run is about. Recorded here anyway because it
is a fact about **codex 0.154.0** and this is the page a future reader opens.
Step 6 above says this page may be annotated freely.

**`approval_policy = "untrusted"` is RETIRED.** The upstream docs at
`262d53df92e9cf7495206e64e3f6c4edc757116f` add a whole section for it —
*"Codex and ChatGPT Work no longer support `approval_policy = "untrusted"`. The
retired setting can prevent either client from starting."* — and the config
reference drops `untrusted` from the `approval_policy` type union:

```diff
-      type: "untrusted | on-request | never | { granular = { … } }",
+      type: "on-request | never | { granular = { … } }",
```

**None of the six curated release-note sections mentions this.** It is reachable
only through the docs repo. That is the finding worth keeping: a curated
changelog is a SUMMARY, and a start-blocking config retirement can sit outside
it. A version bump's review is not complete at the release notes.

**Checked here, both configs, and we are safe:**

| config | `approval_policy` | verdict |
|---|---|---|
| `.codex/config.toml` (project, 265 lines) | absent | unaffected. Control arm: `wc -l` returns 265, so rc=1 is a real "no match" and not an unreadable path — the first attempt at this probe ran from the wrong cwd and reported "No such file or directory", which reads identically to a clean negative |
| `~/.codex/config.toml` (user-global, 653 lines) | `"never"` at line 4 | unaffected. READ ONLY — `do-not.md` #11 forbids this repo writing that file |

**Do not overstate it.** `untrusted` is retired as an `approval_policy` VALUE.
The same diff still uses `trust_level = "untrusted"`, a different key that is
alive. The retirement is scoped to one setting, not to the word.
